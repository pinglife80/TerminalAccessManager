## Summary

### 改动 3：新增 IP/MAC 去重 / 查重筛选（两个下拉）

**用户已确认**：
- 判定维度：`ip`（按 IP）/ `mac`（按 MAC）/ `both`（IP 与 MAC 都算）。
- 形态：两个下拉 = 「维度」+「模式（去重 / 仅重复）」。

#### 3.1 后端 schema `backend/app/schemas/terminal.py`
- `TerminalQuery` 新增：
  ```python
  dedup_dim: str | None = Field(None, description="Dedup/duplicate key: ip/mac/both")
  dedup_mode: str | None = Field(None, description="Dedup mode: dedup/duplicates")
  ```

#### 3.2 后端 endpoint `backend/app/api/v1/endpoints/terminals.py`
- `/search` 新增 `dedup_dim: str = Query(None)`、`dedup_mode: str = Query(None)`，并传入 `TerminalQuery`。

#### 3.3 后端 service `backend/app/services/terminal_service.py`

将 `search_macs` / `search_macs_count` 中现有的 conditions 构建**收敛为一份基础条件** `base_conditions`（等同移除 block_state/arp_enabled_only 后的现有条件），再按 `dedup_mode` 追加处理。语义如下：

- **`duplicates`（仅重复）**：只返回「判定键重复」的条目。
  - `dim=ip`：`ip_address IN (SELECT ip_address ... GROUP BY ip_address HAVING count(*) > 1)`
  - `dim=mac`：`mac_address_normalized IN (SELECT ... GROUP BY mac_address_normalized HAVING count(*) > 1)`
  - `dim=both`：上述两个条件取 `or_`（IP 重复 或 MAC 重复）。
  - 计数 = 在满足上述条件基础上的 `count(Terminal.id)`。

- **`dedup`（去重）**：每个判定键只保留最新一条（`timestamp DESC, id DESC`）。
  - `dim=ip`：按 `ip_address` 去重。
  - `dim=mac`：按 `mac_address_normalized` 去重。
  - `dim=both`：因 MAC 唯一，去重等价于按 `ip_address` 去重（说明见下方「假设与决策」）。
  - 实现采用 PostgreSQL 窗口函数（标准、通用）：
    ```python
    key_col = Terminal.mac_address_normalized if dim == "mac" else Terminal.ip_address
    rn = func.row_number().over(
        partition_by=key_col,
        order_by=(Terminal.timestamp.desc(), Terminal.id.desc()),
    ).label("rn")
    sub = select(Terminal, rn).where(and_(*base_conditions)).subquery()
    stmt = (
        select(Terminal)
        .select_from(sub)
        .where(sub.c.rn == 1)
        .order_by(sub.c.timestamp.desc(), sub.c.id.desc())
        .offset(query.skip)
        .limit(query.limit)
    )
    ```
  - 计数 = `count(distinct key_col)`，其中 `key_col` 对 `ip`/`both` 为 `ip_address`，对 `mac` 为 `mac_address_normalized`（在 `base_conditions` 之上）。

- 未传 `dedup_mode` 时不加任何去重/查重处理（走原有逻辑）。

> 实现注意：若 `select(Terminal).select_from(sub) ...` 的实体映射在 SQLAlchemy 2.0 下报列归属异常，退化为显式列选择 `select(sub)`，再在返回前构造 `Terminal` 响应字段；执行时以实际报错为准，二者结果等价。

#### 3.4 前端 `frontend/src/hooks/useTerminalData.ts`
- `TerminalSearchParams` 新增：
  ```ts
  dedup_dim?: 'ip' | 'mac' | 'both';
  dedup_mode?: 'dedup' | 'duplicates';
  ```

#### 3.5 前端 `frontend/src/pages/Terminals.tsx`
- 新增两个 state：
  - `filterDedupDim`（默认 `'ip'`）
  - `filterDedupMode`（默认 `''`，即不过滤）

  1. **维度**：按 IP / 按 MAC / IP 与 MAC 都算（值 `ip`/`mac`/`both`）。
  2. **模式**：不过滤 / 去重 / 仅重复（值 `''`/`dedup`/`duplicates`）。
- `useTerminals(...)` 传入 `dedup_dim`（仅当 `dedup_mode` 非空）、`dedup_mode`（非空时）。
- 选择变化时 `setCurrentPage(1)`。
- `handleReset`（若有统一 reset）同时重置这两个 state。

#### 3.6 前端 i18n（`zh.ts` / `en.ts` / `ja.ts`）

## Assumptions & Decisions

1. **「按MAC去重/查重」在真实数据上基本为空**：因 `mac_address_normalized` 唯一，MAC 无重复；该维度仅对 `mac_address_normalized IS NULL` 的历史异常记录有意义。保留该维度以满足用户「既可以按 IP，也可以按 MAC，还可以都算」的诉求，不做额外特殊处理。
2. **`both` 去重等价于按 IP 去重**：因为 MAC 维度不重复，联合去重结果与按 IP 去重一致。实现上 `both` 与 `ip` 共用 `ip_address` 作为去重键，避免语义歧义与过度设计。
3. **去重「保留最新」**：统一取 `timestamp DESC, id DESC` 的第一条。
4. **移除的是「过滤」，不是「状态/业务」**：`block_state` 字段、列表徽标、后端设置逻辑、`pending_retry_block`/`unblockable_non_compliant` 统计口径全部保留，仅删除「作为列表过滤条件」的入口与参数。
5. **黑名单页两个卡片跳转降级**：移除 `arp_enabled_only` / `block_state` 参数后，「等待重试封锁」与「无法封锁的非合规」跳转都变为 `compliance_status=non_compliant&status=unblocked`，区分度降低；这是移除这两个过滤参数的必然结果，不做额外补救（避免引入新东西）。
