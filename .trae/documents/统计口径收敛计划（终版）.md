# 统计口径收敛计划（终版）

> 修订原因：v2.0 把领域模型错误地压成「合规轴=MAC / 封锁轴=IP」的二元论，并臆造了「跨防火墙去重」「stats_basis.py 三键抽象」等不存在的问题。本版先纠正领域模型，再把唯一的真实口径错位收敛掉，最后做前端分层展示。不引入任何新抽象。

## 一、领域模型（正确版，本计划的地基）

### 1. 合规判定是「终端」维度，判定规则早已明确定义

对每条 ARP 终端（Terminal 行，含 `ip_address` + `mac_address`），判定流程见
[compliance_service.py](file:///home/dada/Codespace/TraeCN/TerminalAccessManager/backend/app/services/compliance_service.py#L175-L205)：

1. **先比白名单** `_match_whitelist_in_memory`（[L1035-L1075](file:///home/dada/Codespace/TraeCN/TerminalAccessManager/backend/app/services/compliance_service.py#L1035-L1075)）：
   - `mac_only` 只比 MAC；`single_ip`/`cidr`/`ip_range` 只比 IP；`both` 比 IP+MAC。
   - 命中 → `bypass`。
2. **非白名单 → 按 scope 规则选合规比对策略** `_check_terminal_in_arp_scope`（[L1285-L1324](file:///home/dada/Codespace/TraeCN/TerminalAccessManager/backend/app/services/compliance_service.py#L1285-L1324)），scope_type ∈ `ip_cidr`/`ip_range`/`mac_prefix_arp`：
   - 落入 scope → 纯 IP 比对（`_match_ipguard_ip_only_in_memory`）；
   - 否则 → IP+MAC 比对（`_match_ipguard_in_memory`，精确 IP+MAC 或 IP+MAC 前缀）。
3. **IPGuard 命中 → `compliant`，否则 `non_compliant`**（经 confirm 阈值 / 冷却期 / IP 变更宽限等防抖后落库）。

判定结果 `compliance_status` 写在 Terminal 上。**统计单位是「终端」**（Terminal 行，唯一键
[`uq_terminal_mac`=mac_address_normalized](file:///home/dada/Codespace/TraeCN/TerminalAccessManager/backend/app/models/terminal.py#L48-L52)），
不是「按 MAC 聚合」，更不是「按 IP」。

### 2. 防火墙封锁只有 IP，firewall_tag 是跨防火墙唯一条目的标签属性

封锁动作只传 IP（`block_ip([ip_address])`）。同一 IP 在 N 台防火墙各封一条，Blacklist 的活跃唯一键就是
[`(ip_address, mac_address_normalized, firewall_tag)`](file:///home/dada/Codespace/TraeCN/TerminalAccessManager/backend/app/models/blacklist.py#L40-L42)
——**firewall_tag 正是「同一 IP 跨防火墙唯一条目」的标签属性，天然无重复**，没有也不需要「跨防火墙去重」。

### 3. 对账逐防火墙独立，firewall_ip_count 本就是各防火墙之和

[reconcile](file:///home/dada/Codespace/TraeCN/TerminalAccessManager/backend/app/services/firewall_reconciliation_service.py#L82-L134)
按防火墙独立循环，`results["firewall_ip_count"] += len(fw_ips)`（[L133-L134](file:///home/dada/Codespace/TraeCN/TerminalAccessManager/backend/app/services/firewall_reconciliation_service.py#L133-L134)），
即各防火墙封锁 IP 之和，正确，无需改动。

## 二、撤销 v2.0 的臆造（本次不做）

- **撤销「跨防火墙去重」**：字段本身由 `firewall_tag` 唯一区分，无重复问题，没有这一步改动。
- **撤销「合规轴=MAC / 封锁轴=IP」二元论**：合规是「终端」维度；封锁才是「IP / (ip, firewall_tag)」维度。

- **ARF helper 抽取（v2.0 的 P1-1）已在上轮完成**：`get_blacklist_stats` 已复用
  [`_enabled_arp_source_tag_condition()`](file:///home/dada/Codespace/TraeCN/TerminalAccessManager/backend/app/services/terminal_service.py#L61-L70)，此处不再改动。

## 三、真实口径错位（唯一需要修的点）

[`get_stats`](file:///home/dada/Codespace/TraeCN/TerminalAccessManager/backend/app/services/terminal_service.py#L254-L341) 里只有 `non_compliant` 一个字段是封锁轴口径，导致两个轴的数被放在一起比大小：

| 字段 | 当前口径 | 应属维度 |
|---|---|---|
| `total` | Terminal 行数 | 终端 |
| `compliant` / `bypass` / `unknown` | Terminal 行数 | 终端 |
| **`non_compliant`** | **`count(distinct ip)` where non_compliant & blocked** | **错位（IP）** |
| `non_compliant_unblocked` | Terminal 行数 | 终端 |
| `blocked` | `count(distinct active blacklist ip)` | IP（封锁，正确） |

把 `non_compliant` 收敛回终端数后，合规序列即可自洽：`total = compliant + bypass + non_compliant + unknown`（全是终端数，可加和）。

## 五、Assumptions & Decisions

- **`non_compliant` 语义 = 「非合规终端数」**（合规轴，与 compliant/bypass/unknown/total 可加和）。这是本计划的默认决策；若你仍需它表示「非合规且已封锁的 IP 数」，则 P1 回退、仅保留 P2 注释即可。
- **`blocked` 语义 = 「活跃黑名单 distinct IP 数」**（封锁轴），维持不变，与黑名单页 `success_blocked`、防火墙实际状态同轴。
- **`firewall_ip_count`、`get_stats` 的 distinct IP、`pending_retry_unblock` 的 coalesce** 各自在正确语境，不做改动。
- 本次不新建任何抽象文件（无 `stats_basis.py`），只改一处后端口径 + 前端分层展示 + 注释/文案。
