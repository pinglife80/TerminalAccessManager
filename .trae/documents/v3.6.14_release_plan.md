## 三、发布流程（遵循 Git Flow）

### 3.1 步骤一：提交工作区变更

将未提交的变更分批提交到 develop 分支：

```bash
# 提交后端代码变更
git add backend/app/services/compliance_service.py \
        backend/app/services/terminal_service.py \
        backend/app/schemas/terminal.py \
        backend/app/api/v1/endpoints/whitelist.py \
        backend/app/models/whitelist.py \
        backend/alembic/versions/028_whitelist_unique_constraint.py
git commit -m "fix(whitelist): correct pattern_type logic, firewall_tag cleanup, comments required"

# 提交前端代码变更
git add frontend/src/pages/Terminals.tsx \
        frontend/src/pages/Whitelist.tsx \
        frontend/src/i18n/locales/zh.ts \
        frontend/src/i18n/locales/en.ts \
        frontend/src/i18n/locales/ja.ts
git commit -m "fix(whitelist): add match type selector, comments validation, firewall_tag display"

# 提交文档变更
git add docs/
git commit -m "docs: update all documentation to v3.6.14"
```

### 3.2 步骤二：删除旧的 v3.6.14 tag

```bash
# 删除本地 tag
git tag -d v3.6.14

# 删除远程 tag
git push origin :v3.6.14
```

### 3.3 步骤三：创建 Release 分支

```bash
# 确保 develop 分支最新
git checkout develop
git pull origin develop

# 创建 release 分支
git checkout -b release/v3.6.14

# 推送远程
git push -u origin release/v3.6.14
```

### 3.4 步骤四：最终验证

在 release 分支上执行最终验证：

```bash
# 前端构建验证
./manage.sh -y update

# 服务状态验证
./manage.sh status

# 后端测试验证
./manage.sh test-backend

# 前端测试验证
./manage.sh test-frontend
```

### 3.5 步骤五：合并到 Main 分支

```bash
# 切换到 main 分支
git checkout main
git pull origin main

# 合并 release 分支（使用 --no-ff 保留历史）
git merge --no-ff release/v3.6.14 -m "Merge release/v3.6.14 into main"

# 推送 main
git push origin main
```

### 3.6 步骤六：创建新的 Tag

```bash
# 创建带注释的 tag
git tag -a v3.6.14 -m "release v3.6.14: whitelist matching logic fix, firewall_tag cleanup, comments required"

# 推送 tag
git push origin v3.6.14
```

### 3.7 步骤七：合并到 Develop 分支

```bash
# 切换到 develop 分支
git checkout develop

# 合并 release 分支
git merge --no-ff release/v3.6.14 -m "Merge release/v3.6.14 into develop"

# 推送 develop
git push origin develop
```

### 3.8 步骤八：删除 Release 分支

```bash
# 删除本地 release 分支
git branch -d release/v3.6.14

# 删除远程 release 分支
git push origin --delete release/v3.6.14
```

## 五、回滚方案

如果发布后发现问题，执行以下回滚步骤：

```bash
# 回滚 main 分支到上一个 tag
git checkout main
git reset --hard v3.6.13
git push origin main --force

# 回滚 develop 分支
git checkout develop
git reset --hard <回滚前的 commit hash>
git push origin develop --force

# 删除错误的 tag
git tag -d v3.6.14
git push origin :v3.6.14
```
