## 三、计划步骤

### 第 0 步：提交前本地验证（可选但推荐）

```bash
# 后端 lint + 测试
cd backend && ruff check app/ && python -m pytest tests/ -q

# 前端 lint + 测试
cd frontend && npx eslint . --ext ts,tsx --max-warnings 25 && npx vitest run
```

> 本项目统一入口：`./manage.sh test`（如需，则以 `manage.sh` 为准替代上述命令）。

### 第 1 步：清理旧 version bump 遗留的伪改动

依据本次确定的「全项目版本号统一从 `VERSION` 动态派生」原则，`package.json` / `package-lock.json` 的版本号由 `frontend/Dockerfile` 在镜像构建期动态同步，不属于发布人工步骤。故丢弃工作区里由旧版 `version bump` 产生的这两处伪改动（`VERSION` 会在第 3 步被重写，无需单独处理）：

```bash
git checkout -- frontend/package.json frontend/package-lock.json
```

> 执行后 `git status --short` 中不再出现 `package.json` / `package-lock.json`。

### 第 2 步：功能代码提交（develop，Conventional Commits）

按逻辑拆分为 4 个提交，后端/前端/工具链分离：

```bash
# 1) 后端：到期解封写入独立 reason
git add backend/app/services/terminal_service.py \
        backend/tests/test_compliance_service.py
git commit -m "fix(blacklist): record unblock reason when blacklist entry expires"

# 2) 前端：黑名单「解封事件」列 + i18n
git add frontend/src/pages/Blacklist.tsx \
        frontend/src/i18n/locales/zh.ts \
        frontend/src/i18n/locales/en.ts \
        frontend/src/i18n/locales/ja.ts
git commit -m "feat(blacklist): add unblock-event column showing reason and time"

# 3) 数据库：SQLite 连接池参数适配
git add backend/app/core/database.py
git commit -m "fix(database): apply connection-pool params only for non-SQLite databases"

# 4) 工具链：manage.sh 版本管理逻辑修正
git add manage.sh
git commit -m "fix(deploy): source all version references dynamically from VERSION"
```

### 第 3 步：文档内容更新 + 版本号递增

1. 用修正后的 `version bump`（仅写 `VERSION`）：

```bash
./manage.sh version bump 3.16.0
```

1. 按「四、文档变更明细」编辑 4 个文档文件：

   * `docs/changelog.md`：文档头版本号 + 新增 `[3.16.0]` 条目

   * `docs/release-notes.md`：文档头版本号 + 新增 `[v3.16.0]` 发布记录

   * `docs/production-readiness-assessment.md`：版本跟踪表新增 v3.16.0 行

   * `docs/business-workflow.md`：文档头版本号 `v3.15.0` → `v3.16.0`

2. 提交发布提交（含 `VERSION`、4 个文档、以及 `.trae/documents` 下 3 个计划文档）：

```bash
git add VERSION \
        docs/changelog.md \
        docs/release-notes.md \
        docs/production-readiness-assessment.md \
        docs/business-workflow.md \
        .trae/documents/
git commit -m "chore(release): bump version to v3.16.0 and refresh docs"
```

### 第 4 步：推送 develop

```bash
git push origin develop
```

> 推送会触发 CI（lint/test/build）。确认 4 项关键 status check 通过。

### 第 5 步：手动 PR（develop → main）

在 GitHub 上创建 Pull Request：

* Base：`main` ← Compare：`develop`

* 标题建议：`release: v3.16.0 黑名单解封事件列与到期解封 reason`

* 描述：粘贴 `docs/changelog.md` 中 `[3.16.0]` 条目内容

* 等待 CI（`backend-lint`/`backend-test`/`frontend-lint`/`frontend-test`）全部通过

* 自审 diff 后选择 **Merge**（不 squash、不删除 develop）

### 第 6 步：打 tag（PR 合并后）

PR 合并后（`main` 已含 v3.16.0 内容，满足「仅 PR 合并后可打 tag」约束）：

```bash
git checkout main
git pull origin main
git tag -a v3.16.0 -m "release v3.16.0: blacklist unblock-event column and expiry reason"
git push origin v3.16.0
```

### 第 7 步：同步 develop

```bash
git checkout develop
git merge main
git push origin develop
```

> 因 develop 的 tip（发布提交）是 main 合并提交的祖先，此步骤通常为 fast-forward，develop 与 main 收敛到同一点。

### 第 8 步（可选）：GitHub Release

在 GitHub 上基于 tag `v3.16.0` 创建 Release，Release notes 从 `docs/changelog.md` 的 `[3.16.0]` 条目复制。

## 五、假设与决策

1. **发布版本号取 Minor（v3.16.0）**：本批包含新 UI 能力（黑名单「解封事件」列），符合语义化版本 Minor 递增规则（git-workflow-guide §2）。已与用户确认。
2. **发布时间戳统一为** **`2026-08-25`**（当前本地日期）。
3. **`package.json`/`package-lock.json`** **版本号不手动同步**：依据本次确立的「全项目版本号统一从 `VERSION` 动态派生」原则，二者由 `frontend/Dockerfile` 在镜像构建期 `sed` 同步；发布人工步骤中丢弃旧版 `version bump` 遗留的这两处伪改动，不纳入提交。
4. **`VERSION`** **的换行差异**：历史提交的 `VERSION` 无末尾换行，修正后的 `version bump` 用 `echo` 写入会带换行；此差异仅影响格式化，属可接受范围，且发布后即为新基线。
5. **走「直接提交 develop + 发布 PR」流程**：沿用 v3.13.0/v3.14.0/v3.15.0 的实际做法（特性提交直接在 develop，发布经 develop → main 的 PR），而非为本次特性再开 feature 分支；「手动 PR」即 develop → main 发布 PR。
6. **计划文档随发布提交纳入版本控制**：`.trae/documents` 下 2 个既有计划文档 + 本计划文档，作为纯文本文档一并提交（`.trae/` 已在上一次发布重新纳入跟踪）。
7. **`docs/release-plan.md`、`README.md`** **不纳入本次同步**：v3.15.0 发布提交未触碰它们，非每次发布的必更文档。
8. **业务链/构建验证已在前序会话完成**：黑名单到期解封 reason 的单测断言、前端 tsc/vite 构建、manage.sh 版本逻辑的语法检查与 `version check` 实测均已通过；本计划聚焦版本/文档/流程动作，不重复实现代码。
