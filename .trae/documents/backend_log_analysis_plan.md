# 后端日志问题分析与修复计划

## 问题概述

通过分析后端运行日志，发现存在三个主要问题，按严重程度排序：

1. **数据库连接泄漏（严重）** - SQLAlchemy连接池中的连接未正确归还
2. **邮件发送限流（中等）** - 邮件服务达到发送频率限制
3. **Sangfor防火墙并发限制（中等）** - 防火墙API连接数超过上限

---

## 问题1：数据库连接泄漏

### 根因分析

日志显示：
```
The garbage collector is trying to clean up non-checked-in connection <AdaptedConnection ...>
```

**原因**：
- 虽然 `get_db()` 依赖使用了 `async with` 上下文管理器，但在某些异步操作中，连接可能没有被正确释放
- 特别是在合规计算服务中，批量更新终端状态时可能存在连接生命周期管理问题
- 垃圾回收器发现未归还给连接池的连接，强制终止它们

**影响**：
- 连接池资源耗尽
- 数据库性能下降
- 可能导致服务无法响应

### 修复方案

1. 检查 `compliance_service.py` 中的数据库操作，确保所有会话都正确使用上下文管理器
2. 在关键操作后显式调用 `await session.flush()` 和 `await session.commit()`
3. 考虑增加连接池配置，设置合理的超时和回收策略

---

## 问题2：邮件发送限流

### 根因分析

日志显示：
```
Failed to send email to qiangnian.zheng@inceptio.ai: Rate limit exceeded
```

**原因**：
- 合规计算触发了大量终端状态变化（从 `non_compliant` 到 `bypass`）
- 每个状态变化都会触发通知发送
- 邮件服务对单个收件人有发送频率限制

**影响**：
- 部分通知无法发送
- 用户无法及时收到告警信息
- 日志被大量错误信息淹没

### 修复方案

1. 在邮件发送前检查限流状态，避免无效重试
2. 实现通知去重和合并机制，减少重复发送
3. 配置合理的通知频率限制
4. 考虑使用异步队列进行邮件发送，避免阻塞

---

## 问题3：Sangfor防火墙并发限制

### 根因分析

日志显示：
```
Sangfor AF login failed: code=1, message=当前在线用户已超过最大并发用户限制
```

**原因**：
- 合规计算期间大量终端状态变化需要同步到防火墙
- 每个封锁/解封操作都需要建立新的API连接
- 深信服防火墙对单个用户的并发连接数有限制

**影响**：
- 封锁/解封操作失败
- 防火墙与数据库状态不一致
- 合规策略无法正确执行

### 修复方案

1. 实现 Sangfor API 连接池，复用连接而非每次创建新连接
2. 在认证失败后增加指数退避重试机制
3. 限制并发操作数量，避免超过防火墙限制
4. 实现操作队列，顺序处理防火墙命令

- **Sangfor连接池**：需要确保线程安全，避免连接共享问题
