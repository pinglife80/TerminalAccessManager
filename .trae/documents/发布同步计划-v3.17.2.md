## 六、推送与 PR

> 前置：本次改动位于 `main` 工作区，须先迁至 `develop`。

1. **迁移未提交改动到 develop**：
   ```bash
   git stash push -u -m "WIP: v3.17.2 changes"   # 含未跟踪文档
   git checkout develop
   git pull origin develop
   git stash pop
   ```
   > 因 `main` 与 `develop` 当前内容一致（main 为 develop 的 PR #42 合并），`git checkout develop` 本身即可携带未提交改动；用 `stash` 仅为稳妥起见。

2. **提交前验证**（在 develop 上）：
   ```bash
   ./manage.sh update          # 本地重建 + 重启，确认构建/TS 编译无错
   docker exec tam_backend python -m pytest -q   # 后端回归（预期 1473 passed）
   ```

3. **按「五、提交计划」依次 commit**。

4. **推送 develop**：`git push origin develop`（含提交 1–10，共 10 个）。

5. **手动创建 PR**（GitHub：`develop` → `main`）：
   * 标题：`release: v3.17.2 RBAC 加固、i18n 补全与暗色模式统一`
   * 描述：粘贴 `docs/changelog.md` 的 `[3.17.2]` 条目
   * 复核 `backend-lint / backend-test / frontend-lint / frontend-test` 四项 CI 均通过
   * 自审 diff 后选择 **Merge**（Merge commit，沿用既有习惯；不 squash、不删除 develop）

## 七、打 tag 与 develop 同步

> 依据项目约束「Git tag 仅打于 main、且须 PR 合并后」。

1. PR 合并后，本地同步并切到 main：
   ```bash
   git checkout main && git pull origin main
   ```
2. 打 annotated tag 并推送：
   ```bash
   git tag -a v3.17.2 -m "release v3.17.2: RBAC hardening, i18n completion and dark-mode consistency"
   git push origin v3.17.2
   ```
3. develop 同步 main（含 tag）：
   ```bash
   git checkout develop && git merge main && git push origin develop
   ```
