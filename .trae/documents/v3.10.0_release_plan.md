### 变更分类

**变更A：备份管理完备性修复（7 项）**

1. 白名单备份不受 `backup_whitelist` 选项控制 → 添加条件检查
2. 手动备份端点未加载用户配置 → 添加 `load_config()` 调用
3. 白名单备份端点未加载配置 → 同上
4. 配置文件备份不完整 → 扩展 `nginx.conf`、`alembic.ini`
5. 系统配置DB恢复无事务保护 → 使用 `begin_nested()` 逐表保护
6. 远程备份无过期清理 → 新增 SFTP/FTP 远程清理逻辑
7. 恢复功能不完整 → 新增白名单恢复、配置文件解包、日志恢复

**变更B：告警阈值配置化（4 项 + 1 bug 修复）**

1. 合规率告警阈值 `0.8` 硬编码 → `alert_compliance_rate_threshold`（默认 80）
2. 合规率危险比例 `0.5` 硬编码 → `alert_compliance_critical_ratio`（默认 50）
3. 封锁数量阈值 `50` 硬编码 → `alert_block_count_threshold`（默认 50）
4. 离线检测倍数 `3` 硬编码 → `alert_offline_threshold_multiplier`（默认 3）
5. 修复 `emit_compliance_alert` 中 0-100 与 0-1 量纲不一致导致 `is_critical` 永远为 False 的 bug

### 5.3 合并后操作

PR 合并到 main 后：

1. 切换到 main 分支：`git checkout main && git pull origin main`
2. 打 tag：`git tag -a v3.10.0 -m "release v3.10.0: 备份管理完备性修复与告警阈值配置化"`
3. 推送 tag：`git push origin v3.10.0`

## 八、风险与注意事项

1. **`main.py`** **拆分问题**：`main.py` 同时包含备份审计日志增强（变更A）和合规率阈值配置化（变更B）两处修改，建议合并为单次提交避免 `git add -p` 的复杂性。

2. **文档版本号一致性**：确保所有 P0-P2 文档的头部版本号统一更新为 `v3.10.0`，日期更新为 `2026-08-06`。

3. **数据库种子初始化**：新配置项通过 `seed_defaults()` 在服务启动时自动插入，已有数据库只需重启服务即可。无需手动 SQL 操作。

4. **tag 时机**：tag 必须在 PR 合并到 main 之后打，不能在 develop 分支上打。
