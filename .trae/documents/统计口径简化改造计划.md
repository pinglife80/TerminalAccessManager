# 统计口径简化改造计划（修订版）

> 修订原因：上一版把「去重键」过度设计为三键（distinct IP / 不去重行 / coalesce(MAC,IP)），还臆造了「跨防火墙重复」问题。实际领域模型要简单得多。

---

## 一、Summary

统计数据「对不上」的根因不是去重维度复杂，而是把两个正交维度混在了一排卡片里比大小：

- **合规轴**（终端/MAC）：一个终端一台设备，`compliance_status` 写在 Terminal 上，天然按 MAC 数。
- **封锁轴**（IP）：防火墙只封 IP，`firewall_tag` 只是「在哪台防火墙封」的归属，不是去重维度。

本计划的唯一目标：把统计收敛为**两个轴、两个键**，并让前端三页（Dashboard / 终端 / 黑名单）按轴分层展示，不再混排。

---

## 二、领域模型（已确认，本计划的地基）

1. **合规判定**：[check_compliance / _match_whitelist_in_memory / _match_ipguard_in_memory](file:///home/dada/Codespace/TraeCN/TerminalAccessManager/backend/app/services/compliance_service.py#L102-L151) 按 scope 规则选择「IP-only」或「IP+MAC」去比白名单(IP/MAC/both)与 IPGuard(IP 或 IP+MAC)。判定方式只影响「是否合规」，与统计单位无关。
2. **防火墙封锁**：只有 IP（`block_ip([ip_address])`）。`firewall_tag` 是归属标签，非去重维度。
3. **对账**：[reconcile](file:///home/dada/Codespace/TraeCN/TerminalAccessManager/backend/app/services/firewall_reconciliation_service.py#L34-L182) 按防火墙**独立**循环，`firewall_ip_count` 是各防火墙封锁 IP 之和，本就是正确口径，**无需改动**。

## 三、两个去重键（全部统计只用这两个）

| 轴 | 键 | 适用指标 |
|---|---|---|
| 合规轴 | 终端 MAC（`mac_address_normalized`，Terminal 表唯一） | total / compliant / bypass / non_compliant / unknown |
| 封锁轴 | IP（`ip_address` distinct） | blocked / success_blocked / firewall_ip_count |

说明：`get_stats` / `get_blacklist_stats` 里的 `count()`（终端表查询）其实已等价于 `count(distinct mac)`（Terminal 有 `uq_terminal_mac` 唯一约束），无需改动。

## 四、撤销上一版的过度设计

- 撤销「`firewall_ip_count` 跨防火墙去重」：逐防火墙独立对账，无重复问题。
- 撤销「coalesce(MAC,IP) 三键合一」：合规归 MAC、封锁归 IP，两键即可。
- 撤销「废弃 count() 行」：终端表唯一 MAC，count()==distinct MAC，非问题。

## 五、实际改动（精简，按优先级）

### P1-1　抽取共享 ARP 过滤 helper（唯一必要的后端清理）
- 新增模块级 `enabled_arp_filter()`，替换 [get_stats 的 `_enabled_arp_source_tag_condition()`](file:///home/dada/Codespace/TraeCN/TerminalAccessManager/backend/app/services/terminal_service.py#L61-L70) 与 [get_blacklist_stats 内联的 nc_unblocked_filter ARP 部分](file:///home/dada/Codespace/TraeCN/TerminalAccessManager/backend/app/services/terminal_service.py#L1659-L1667) 这一处重复；两处语义本就一致，仅去重。

### P1-2　口径注释文档化（不改语义）
- 在 `get_stats` / `get_blacklist_stats` 各查询处用注释标注「合规轴=MAC」「封锁轴=IP」，让后续维护者不再混淆两个维度。

### P1-3　前端三页按轴分层 + 精简卡片（消除「混排比大小」错觉）
- **终端页**：`compliant / bypass / unknown / total` 均为 MAC 轴合规卡；「非合规已封锁/待封锁」合并为一张「非合规」卡（MAC 轴），卡内次级显示「其中 status=blocked x · unblocked y」，不再用 IP 口径硬对齐封锁卡。
- **黑名单页**：封锁轴卡片（IP）＝「防火墙实际封锁」（真相源）＋「DB 活跃封锁」（期望值）＋「差异」；「封锁失败待重试 / 不可封锁非合规」合并为一张「待封锁」卡并细分 `no_firewall`。
- **Dashboard**：「已封禁」主数字归封锁轴（IP），副标签显示 DB 与防火墙的差异，明确标注口径。

### P1-4　i18n 清理
- 删除/新增合并后的中英文案，同步 [zh.ts](file:///home/dada/Codespace/TraeCN/TerminalAccessManager/frontend/src/i18n/locales/zh.ts) 与 en。

## 六、Assumptions & Decisions

- 每一张卡片显式标注口径（MAC / IP），用户不再需要「猜」两个轴。
- 「非合规」退回 MAC 轴（与其它合规卡同轴），不再与「封锁 IP」数对齐——这是「数据对不上」观感的直接来源。
- 不对 `firewall_ip_count`、`get_stats` 的 distinct IP、`pending_retry_unblock` 的 coalesce 做任何改动；这些在各自轴内已正确。

## 七、Verification

1. `./manage.sh update` 本地重建后，容器指纹核对前端改动已部署（`docker exec tam_frontend`→实际由 tam_nginx 提供静态资源，核对 nginx 内容）。
2. 三页口径校验：
   - 终端页合规卡（total/正常/绕过/待检查/非合规）按 MAC 数，互相可加和。
   - 黑名单页封锁卡按 IP 数，「防火墙实际」与「DB 活跃」之差 = 待对账差异。
   - Dashboard「已封禁」= 黑名单「防火墙实际」（同轴、同键）。
3. 边界回归：DHCP 换 IP、同 IP 多终端、补建 NULL-MAC 条目下，各卡数字不报错、口径标注正确。
