# 测试覆盖全面评估与补全计划

> 文档版本：规划稿  更新日期：2026-08-26

## 1. 摘要（Summary）

本计划对「终端访问管理器（Terminal Access Manager，TAM）」当前系统各业务链条的测试用例做一次全面体检，回答三个问题：**用例是否完整、测试逻辑是否正确、覆盖是否全面**。

总体结论：**测试覆盖严重不均、且缺少质量与覆盖率门槛。** 当前后端 135 个用例全部通过，但集中在少数模块——核心合规检测链（`compliance_service`）、认证链、安全工具函数有较完整的单测；而 14 个 API 路由、至少 8 个关键服务（防火墙对账、ARP 采集、sangfor 集成、数据源、配置服务等）**完全没有测试**；同时存在若干「永真/占位」级无效断言，以及 `AsyncMock` 被误用作 `AsyncSession` 导致的 mock 保真度缺陷。前端仅 4 个测试文件，页面与 API 逻辑基本无覆盖。

修复策略分阶段推进：先补测试质量与覆盖率基础设施（当前无法度量覆盖），再补核心合规链与认证安全链，最后补齐外围端点与服务。

### 2.3 测试逻辑正确性问题（需修正）

1. **永真/占位断言** — [test\_core.py](file:///home/dada/Codespace/TraeCN/TerminalAccessManager/backend/tests/test_core.py#L107-L113) `test_login_error_messages_are_uniform` 只有 `assert "Invalid credentials" == "Invalid credentials"`，等于没测。
2. **机制存在性弱断言** — [test\_core.py](file:///home/dada/Codespace/TraeCN/TerminalAccessManager/backend/tests/test_core.py#L85-L101) 只断言 `_INSECURE_DEFAULTS` 列表存在/含某个串，未真正触发生产环境启动校验；`test_token_version_functions_exist` 只 `callable()` 不验证行为。
3. **`hasattr`** **模型冒烟** — [test\_blacklist.py](file:///home/dada/Codespace/TraeCN/TerminalAccessManager/backend/tests/test_blacklist.py) 整文件、[test\_terminals.py](file:///home/dada/Codespace/TraeCN/TerminalAccessManager/backend/tests/test_terminals.py#L40-L56) 模型类，价值极低。
4. **`AsyncMock`** **误用为** **`AsyncSession`**（系统性缺陷）— 生产代码 `self.db.add(obj)` / `session.add(log)` 是**同步**方法，但测试用 `AsyncMock()` 作为 db，导致 `add()` 返回协程且不被 await，产生 `RuntimeWarning: coroutine ... was never awaited`（测试输出可见多条）；`assert_called_once` 只证明「被调用」、无法证明「同步入队/正确 commit」。需要引入专用 `AsyncSession` mock：`add/flush/refresh/close` 用同步 `Mock`，`execute/commit/rollback` 用 `AsyncMock`。
5. **断言过弱** — [test\_auth.py](file:///home/dada/Codespace/TraeCN/TerminalAccessManager/backend/tests/test_auth.py#L277-L286) `test_health_check` 断言 `status in (200, 503)`，未锁定具体行为。
6. **认证安全分支缺失** — 未覆盖：连续失败触发锁定、CAPTCHA 阈值触发、2FA 流程、logout 后 token 真正失效、refresh token 过期/吊销、token 版本失效。`test_security.test_login_lockout_flow` 仅测 1 次失败不解锁，未测达到阈值后锁定。

### 2.4 覆盖率基础设施缺口

无 `.coveragerc`、无 `--cov`、无 `--cov-fail-under`、CI 的 pytest 未开启覆盖率，导致「覆盖全面性」无法量化、无法在 CI 中卡门槛防回归。

## 3. 拟议变更（Proposed Changes）

按优先级分四阶段；P0/P1 属「正确性与核心链」，P2/P3 属「补覆盖」。

### P0：测试质量与覆盖率基础设施（先修地基）

1. **引入** **`AsyncSession`** **保真 mock 工具**：在 [conftest.py](file:///home/dada/Codespace/TraeCN/TerminalAccessManager/backend/tests/conftest.py) 增补一个 `make_mock_async_session()` 夹具/工厂，`add/flush` 等同步方法用 `MagicMock`，`execute/commit/rollback/refresh` 用 `AsyncMock`，并让 `execute` 返回可配置的 `Result`（`scalars().all()`、`scalar_one_or_none()`）。将 `test_compliance_service.py`、`test_notification_service.py`、`test_rbac.py` 中 `mock_db = AsyncMock()` 逐步替换，消除「coroutine never awaited」这类假绿。
2. **启用覆盖率并设门槛**：

   * [pyproject.toml](file:///home/dada/Codespace/TraeCN/TerminalAccessManager/backend/pyproject.toml) 增加 `addopts = "--cov=app --cov-report=term-missing"` 与 `[tool.coverage.run]`（`branch=true`、`source=["app"]`，排除 `app/api/v1/api.py` 等聚合器可选项）。

   * [ci.yml](file:///home/dada/Codespace/TraeCN/TerminalAccessManager/.github/workflows/ci.yml) 的 `backend-test` 步骤加 `--cov-fail-under=<基线>`（首期取一个不阻断现有代码的低基线，随补测逐轮上调）。
3. **修正无效断言**：重写 [test\_core.py](file:///home/dada/Codespace/TraeCN/TerminalAccessManager/backend/tests/test_core.py) 三处占位测试为真实行为验证（例如用 `patch.object(config_module, "ENVIRONMENT", "production")` 触发 `sys.exit` / 校验函数真实返回值）。

## 4. 假设与决策（Assumptions & Decisions）

* **评估口径**：以「是否有对应测试文件/用例」定性 + 覆盖率量化（P0 落地后）为准。

* **优先级依据**：项目核心思想为「合规检测准确、稳定、谨慎变更」，故核心合规闭环（采集→检测→封锁/解封→防火墙对账）列为 P1 最高业务优先级；P0 的地基修正在先，避免在错误 mock 模式上叠加新测试。

* **不引入新测试框架**：沿用 pytest/pytest-asyncio/pytest-cov 与现有 `./manage.sh test`（容器内运行）机制。

* **不修生产代码**：本计划仅评估与补测试；发现的生产逻辑问题（若有）单独立项，不在本轮改动生产代码。

* **范围**：本期聚焦后端；前端测试仅做评估提示，不在本期实施。

## 5. 验证（Verification）

1. P0 落地后执行：`./manage.sh test`，确认无新增失败、且「coroutine never awaited」告警明显减少或消失。
2. 覆盖率：`docker compose exec backend python -m pytest tests/ --cov=app --cov-report=term-missing`，记录各模块基线覆盖，并与 CI `--cov-fail-under` 对齐。
3. 每个新增测试文件单独跑一遍确认：`docker compose exec backend python -m pytest tests/<new_file>.py -v`。
4. CI 校验：推送后观察 `backend-test`、`frontend-test`（vitest）不回归。
5. 回归确认：第 14 条「测试逻辑正确性」中已修正的占位断言，改为对真实行为的断言后通过。
