# v3.6.10 发布计划 - 备份管理优化

> 文档版本：v1.0 | 创建日期：2026-07-09
>
> **版本类型**：Patch（向后兼容的bug修复和优化）
> **发布目标**：main分支
> **分支策略**：简化版 Git Flow

---

## 1. 变更概述

### 1.1 变更类型

| 类型 | 说明 | SemVer 影响 |
|------|------|------------|
| `fix` | Bug 修复 | Patch |
| `feat` | 新功能 | Patch（非核心功能） |
| `docs` | 文档更新 | — |

### 1.2 变更摘要

本次发布包含以下备份管理优化内容：

1. **修复手动备份和白名单备份失败问题**
   - `create_archive()` 方法签名参数不匹配
   - `NotificationRule` 模型字段映射错误（不存在的 `conditions` 字段）

2. **新增定时备份白名单选项**
   - `BackupConfig` 添加 `backup_whitelist` 配置字段
   - 前端定时备份设置添加白名单备份复选框
   - API Schema 更新支持新字段

3. **i18n 翻译完善**
   - 中文、英文、日文翻译文件添加白名单备份相关翻译项

## 3. 发布流程

### 3.1 前置条件

- [x] 当前位于 `develop` 分支
- [x] 所有代码变更已提交到 `develop`
- [x] 服务已验证运行正常（`./manage.sh health`）

### 3.2 Git 操作步骤

#### 步骤 1：更新版本号

```bash
# 一键更新所有版本号文件
./manage.sh version bump 3.6.10
```

**版本号更新文件清单**：
- `VERSION`
- `frontend/package.json`
- `.env`
- `.env.example`
- `docker-compose.yml`
- `manage.sh`
- `frontend/vite.config.ts`

#### 步骤 2：更新文档

```bash
# 更新 changelog.md
# 更新 release-notes.md
```

**文档更新内容**：
- `docs/changelog.md`：添加 v3.6.10 变更记录到 `[Unreleased]` 下方
- `docs/release-notes.md`：添加 v3.6.10 发布记录

#### 步骤 3：提交版本准备

```bash
git add VERSION frontend/package.json .env .env.example docker-compose.yml manage.sh frontend/vite.config.ts
git add docs/changelog.md docs/release-notes.md
git commit -m "chore(release): prepare v3.6.10"
git push origin develop
```

#### 步骤 4：创建 PR 合并到 main

> **注意**：根据分支保护规则，main 分支必须通过 PR 合并

1. 在 GitHub 上创建 Pull Request：`develop → main`
2. 等待 CI 运行完成（lint + test + build）
3. CI 通过后合并 PR

#### 步骤 5：打 Tag

```bash
git checkout main
git pull origin main
git tag -a v3.6.10 -m "release v3.6.10: backup management optimization"
git push origin main --tags
```

#### 步骤 6：同步 develop

```bash
git checkout develop
git merge main
git push origin develop
```

#### 步骤 7：创建 GitHub Release

1. 访问 GitHub Releases 页面
2. Draft a new release
3. 选择 tag: `v3.6.10`
4. 填写 Release title: `v3.6.10`
5. 填写 Release notes（从 changelog.md 复制对应版本内容）

## 5. 风险评估

### 5.1 风险清单

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| 版本号更新遗漏 | 低 | 中 | 使用 `./manage.sh version check` 验证 |
| 备份文件格式变更导致恢复失败 | 低 | 高 | 在测试环境验证恢复功能 |
| i18n 翻译缺失导致页面显示异常 | 低 | 中 | 逐一验证三种语言 |
| CI 构建失败 | 低 | 中 | 预发布前运行 `./manage.sh update` 验证 |

### 5.2 回滚方案

如发布后发现严重问题，执行以下回滚操作：

```bash
# 在 main 分支上 revert 本次发布的 commit
git checkout main
git revert <release-commit-hash>
git tag -a v3.6.11 -m "hotfix: rollback v3.6.10"
git push origin main --tags

# 同步 develop
git checkout develop
git merge main
git push origin develop
```
