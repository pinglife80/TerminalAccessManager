## 生产环境升级步骤

### 方式一：使用 `upgrade` 命令（推荐，已pull代码到main后）

```bash
git checkout main
git pull origin main
./manage.sh upgrade
```

`./manage.sh upgrade` 会自动执行：自动备份 → git pull → 重建容器 → 等待健康 → **自动执行** **`alembic upgrade head`** → 验证访问。**不需要单独执行migrate**。

### 方式二：本地代码已更新的情况

如果代码已经是最新（本地已pull）：

```bash
./manage.sh update          # 重建本地代码（不pull）
./manage.sh migrate         # 单独执行数据库迁移
./manage.sh health          # 验证健康
```

### 方式三：分步执行（手动控制）

```bash
git checkout main && git pull origin main
./manage.sh update
./manage.sh migrate
./manage.sh health
```

### 迁移说明

* 迁移 `035_blacklist_fix_sync_issues` 自动执行：

  1. 标记无firewall\_tag的孤儿记录为已解封
  2. 标记无mac\_address\_normalized的孤儿记录为已解封
  3. 去重同一IP+MAC+防火墙的重复记录
  4. 替换唯一索引为 `(ip_address, mac_address, firewall_tag)`
  5. 清理90天前的已解封历史记录

* 迁移会自动备份（`./manage.sh migrate`会提示备份，`./manage.sh upgrade`自动备份）

* 不会丢失有效封锁记录，仅清理历史脏数据

### 升级后验证

1. 执行 `./manage.sh health` 确认所有服务健康
2. 刷新Dashboard/终端列表/黑名单页面，确认三个位置封锁计数一致
3. （可选）登录后手动触发一次防火墙对账：`POST /api/v1/system/firewall-reconciliation`

## 三个命令对比说明

| 命令                    | git pull      | 重建容器      | 自动迁移                    | 适用场景        |
| --------------------- | ------------- | --------- | ----------------------- | ----------- |
| `./manage.sh update`  | ❌ 不pull，用本地代码 | ✅         | ❌                       | 本地代码修改后重建测试 |
| `./manage.sh migrate` | ❌             | ❌（需要服务运行） | ✅                       | 更新后手动执行迁移   |
| `./manage.sh upgrade` | ✅ 自动pull      | ✅         | ✅（默认执行，可--skip-migrate） | 生产环境升级，一步到位 |

**等效关系**：

* `./manage.sh upgrade` ≈ `git pull && ./manage.sh update && ./manage.sh migrate` + 自动备份+验证

* 生产环境升级直接用 `./manage.sh upgrade` 最方便，不需要分步执行。

## 风险 & 回滚

| 风险      | 影响 | 处理                                                  |
| ------- | -- | --------------------------------------------------- |
| 迁移执行失败  | 低  | 回滚到自动备份：`./manage.sh restore <pre_upgrade备份文件>`     |
| CI 失败   | 低  | 修复问题后重新提交，重新push触发CI                                |
| 新代码有bug | 中  | `git revert <merge-commit-hash>` 回退合并，打新patch版本重新发布 |
