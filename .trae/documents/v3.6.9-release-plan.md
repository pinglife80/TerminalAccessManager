## 四、变更详情

### 4.1 数据导出功能

**问题**：前端数据导出仅支持导出当前页数据，无法导出全量数据或按筛选条件导出。

**解决方案**：在后端新增 3 个导出端点，前端改为调用后端 API。

**修改文件**：
- `backend/app/api/v1/endpoints/terminals.py` — 新增 `GET /terminals/export`
- `backend/app/api/v1/endpoints/whitelist.py` — 新增 `GET /whitelist/export`
- `backend/app/api/v1/endpoints/blacklist.py` — 新增 `GET /blacklist/export`
- `frontend/src/pages/Terminals.tsx` — 修改 `handleExport` 调用后端 API
- `frontend/src/pages/Whitelist.tsx` — 修改 `handleExport` 调用后端 API
- `frontend/src/pages/Blacklist.tsx` — 修改 `handleExport` 调用后端 API
- `frontend/src/lib/constants.ts` — 添加 3 个新 API 端点常量

### 4.2 通知渠道 500 错误

**问题**：创建通知渠道时报 500 内部错误，但实际渠道已创建成功。

**解决方案**：`notifications.py` 中 `channel.channel_type` 改为 `channel.type`（数据库模型字段名）。

**修改文件**：
- `backend/app/api/v1/endpoints/notifications.py` — 修复属性访问错误

### 4.3 合规判断逻辑一致性

**问题**：ARP 采集和定时任务的合规检查路径与白名单变更触发的全量重算路径行为不一致。

**解决方案**：抽取 `_apply_compliance_result` 共享方法，确保所有路径行为一致。

**修改文件**：
- `backend/app/services/compliance_service.py` — 新增 `_apply_compliance_result` 方法，修改 `recalculate_all_compliance` 和 `batch_check_compliance`
- `backend/app/services/arp_collector_service.py` — 使用共享方法
- `backend/app/main.py` — 定时任务使用共享方法

**功能一致性对比**：

| 功能 | 修改前（ARP/定时） | 修改后（统一） |
|------|------------------|---------------|
| 更新 comments（白名单备注） | ❌ | ✅ |
| 触发事件通知 | ❌ | ✅ |
| 自动解封 | ❌ | ✅ |
| 自动封堵（同步） | ❌（异步） | ✅（同步） |

## 五、验证方案

### 5.1 构建验证

```bash
./manage.sh version check  # 验证版本一致性
./manage.sh -y update      # 构建
./manage.sh health         # 健康检查
```

### 5.2 数据导出验证

| 场景 | 操作 | 预期结果 |
|------|------|----------|
| 终端全量导出 | 点击导出按钮（无筛选） | 下载完整 CSV 文件 |
| 终端筛选导出 | 设置筛选条件后点击导出 | 下载符合条件的 CSV 文件 |
| 白名单导出 | 点击导出按钮 | 下载完整 CSV 文件 |
| 黑名单导出 | 点击导出按钮 | 下载完整 CSV 文件 |

### 5.3 合规逻辑验证

| 场景 | 操作 | 预期结果 |
|------|------|----------|
| ARP采集白名单终端 | 添加白名单网段 → 触发 ARP 采集 | `compliance_status=bypass`，`comments` 包含白名单备注 |
| ARP采集不合规终端 | IP 不在白名单/IPGuard → 触发 ARP 采集 | `compliance_status=non_compliant`，触发自动封堵 |
| 定时检查事件触发 | 设置终端为 unknown → 等待定时任务 | 状态更新后触发对应事件 |
| 白名单变更自动解封 | 终端被封堵 → 添加到白名单 | 终端自动解封，`status=unblocked` |

### 5.4 数据一致性验证

| 验证项 | SQL 查询 | 预期结果 |
|--------|---------|----------|
| bypass 终端备注完整性 | `SELECT COUNT(*) FROM terminals WHERE compliance_status='bypass' AND comments IS NULL` | 0 |
| bypass 终端 wl_match_type | `SELECT COUNT(*) FROM terminals WHERE compliance_status='bypass' AND wl_match_type IS NULL` | 0 |

## 七、发布流程

1. **版本号更新**：`./manage.sh version bump 3.6.9`
2. **文档更新**：更新 changelog.md、release-notes.md、技术文档
3. **代码提交**：`git add . && git commit -m "chore(release): v3.6.9 - 合规逻辑一致性优化"`
4. **推送分支**：`git push origin develop`
5. **创建 PR**：从 develop 到 main
6. **代码审查**：等待 CI 通过和人工审查
7. **合并 PR**：merge 到 main
