# 统计口径收敛改造计划

> 本文是《统计分类与数据口径说明.md》结论的落地计划。目标只有一个：**消除三种口径并存导致的“数据对不上”，收敛到以防火墙实际状态为唯一真相源，并精简跨页重复卡片。**

---

## 一、目标

1. **唯一真相源**：所有“已封锁”数字统一来自对账结果（防火墙实际上报），不再以 DB 黑名单记录或终端 `status` 作为“封锁数”主口径。
2. **DB 数字降级**：DB 侧只保留“期望值/待对账差异”，作为对账收敛进度，而不是并列的第二套真相。
3. **卡片精简**：Dashboard / 终端 / 黑名单三页卡片去重、口径一致、可互相解释。

---

## 二、现状盘点（口径冲突点）

| 页面 | 卡片 | 后端字段 | 现有口径 | 问题 |
|---|---|---|---|---|
| Dashboard | 已封禁 | `stats.blocked` | 活跃黑名单 **distinct IP** | 与黑名单“成功封锁”重复，且非真相 |
| 终端 | 非合规已封锁 | `stats.non_compliant` | `non_compliant + blocked` distinct IP | 与 blocked 概念重叠 |
| 终端 | 非合规待封锁 | `stats.non_compliant_unblocked` | `non_compliant + unblocked` | 与黑名单两张卡拆开的同一批 |
| 黑名单 | 成功封锁 | `success_blocked` | 活跃黑名单 distinct IP | = Dashboard 的 blocked，重复 |
| 黑名单 | 防火墙实际封锁 | `firewall_ip_count` | 各防火墙上报 IP **求和不去重** | 唯一真相，但只是数字、无清单 |
| 黑名单 | 封锁失败待重试 | `pending_retry_block` | `non_compliant + unblocked` 且 `block_state∈(None,block_failed)` | 终端页“待封锁”的子集 |
| 黑名单 | 不可封锁非合规 | `unblockable_non_compliant` | 同上且 `block_state=no_firewall` | 终端页“待封锁”的另一个子集 |

关键结构事实（改造依据）：

- 对账服务 [firewall_reconciliation_service.py](file:///home/dada/Codespace/TraeCN/TerminalAccessManager/backend/app/services/firewall_reconciliation_service.py#L34-L160) 已逐防火墙算出 `all_fw_ips`（去重前）、`missing_in_db`、`missing_in_firewall`，但 [_cache_reconcile_result](file:///home/dada/Codespace/TraeCN/TerminalAccessManager/backend/app/main.py#L85-L101) 只把**计数**写进 `reconcile:latest`，**没存 IP 清单/差异清单**。
- 同一 ARP 源过滤逻辑存在多处内联：[_enabled_arp_source_tag_condition](file:///home/dada/Codespace/TraeCN/TerminalAccessManager/backend/app/services/terminal_service.py#L61-L70)（get_stats 用）与 [get_blacklist_stats 内联](file:///home/dada/Codespace/TraeCN/TerminalAccessManager/backend/app/services/terminal_service.py#L1659-L1667)（且后者少包一层 `_enabled_arp_source_tag_condition` 的 `select` 语义），存在分叉风险。

## 三、改造步骤与优先级

### P0 阶段（基础，必须先做——没有真相源清单，后续收敛都无从谈起）

**P0-1　升级对账缓存：把“数字”升级为“清单”**
- 修改 [main.py `_cache_reconcile_result`](file:///home/dada/Codespace/TraeCN/TerminalAccessManager/backend/app/main.py#L85-L101) 与 [trigger_reconcile.py](file:///home/dada/Codespace/TraeCN/TerminalAccessManager/backend/trigger_reconcile.py#L24-L35)，把下面内容一并写入 `reconcile:latest`（TTL 仍 1h）：
  - `firewall_ipset`：跨防火墙**去重后**的封锁 IP 集合（真相源）。
  - `db_active_ipset`：DB 活跃黑名单去重 IP 集合（期望值）。
  - `missing_in_db` / `missing_in_firewall`：两方向差异清单（含 firewall_tag）。
  - 保留 `firewall_ip_count`（用于过渡期兼容）。
- 说明：对账服务里已有 `all_fw_ips` 与 `missing_*`，只是索引/去重前需要做一次 `set` 归一（见 §二 结构事实）。

**P0-2　统一去重与过滤规则为共享 helper**
- 新增/抽取 `app/services/stats_basis.py`（或 `terminal_service.py` 内模块级函数），把三处逻辑收敛成三个真函数：
  - `blocked_truth_key()`：封锁维度一律 **IP**（防火墙按 IP 封，一条规则）。
  - `terminal_identity_key()`：终端维度一律 **MAC 归一化，NULL 回退 IP**（即现有 `_blacklist_terminal_key`）。
  - `enabled_arp_filter()`：统一复用 [_enabled_arp_source_tag_condition](file:///home/dada/Codespace/TraeCN/TerminalAccessManager/backend/app/services/terminal_service.py#L61-L70)，删除 [get_blacklist_stats 内联](file:///home/dada/Codespace/TraeCN/TerminalAccessManager/backend/app/services/terminal_service.py#L1659-L1667) 的重复实现。

### P1 阶段（核心——接口与页面收敛）

**P1-1　合并统计接口为统一输出模型**
- 新增 `get_unified_stats()`，返回一套同时覆盖三页的字段（语义替代现有两个接口）：
  - `blocked`（真相）= `len(firewall_ipset)`；`blocked_db`（期望）= `len(db_active_ipset)`；`blocked_diff`（偏差，可正负）。
  - `non_compliant`（终端维度，仅 `compliance_status='non_compliant'`，**不再叠加 status 条件**）。
  - `pending_block` = `non_compliant + unblocked`，并带 `no_firewall` / `block_failed` 细分计数。
  - `pending_unblock`（原 `pending_retry_unblock`）。
  - `firewall_errors` / `synced_at`。
- 保留 `get_stats` / `get_blacklist_stats` 作为薄壳转发（过渡期不破坏现有前端），并在 docstring 标注“deprecated → get_unified_stats”。

**P1-2　Dashboard：已封禁改真相源**
- [Dashboard.tsx 已封禁卡片](file:///home/dada/Codespace/TraeCN/TerminalAccessManager/frontend/src/pages/Dashboard.tsx#L196-L209) 主数字改用 `blocked`（truth），副标签显示 `DB 偏差 ±blocked_diff`；对账缓存为空时降级显示 DB 数并标注“未对账”。

**P1-3　终端页：6 卡收成 4+1**
- [Terminals.tsx 统计区](file:///home/dada/Codespace/TraeCN/TerminalAccessManager/frontend/src/pages/Terminals.tsx#L727-L789) 保留“总数 / 正常 / 绕过 / 待检查”四张合规卡，把“非合规已封锁 / 非合规待封锁”合并为**一张“非合规”卡**，卡内主数字 + 次级“已封 x · 待封 y”，不再单列两张卡。

**P1-4　黑名单页：7 卡收成 4 卡**
- [Blacklist.tsx 统计区](file:///home/dada/Codespace/TraeCN/TerminalAccessManager/frontend/src/pages/Blacklist.tsx#L169-L278) 收敛为：
  1. **已封锁**（主=防火墙实际，次=DB 记录 + 偏差）——合并“成功封锁”“防火墙实际封锁”。
  2. **待封锁**（主=待封锁总数，次=`no_firewall n`）——合并“封锁失败待重试”“不可封锁非合规”。
  3. **待解封 / 已解封**——保留。
  4. **异常防火墙**——保留。
- 过滤/跳转逻辑随之切换为消费 `get_unified_stats` 的细分字段。

**P1-5　i18n 清理**
- 删除不再使用的 key（`statsSuccessBlocked`、`statsFirewallBlocked`、`statsPendingRetryBlock`、`statsUnblockable` 等），新增差异/合并后的文案，保持 [zh.ts](file:///home/dada/Codespace/TraeCN/TerminalAccessManager/frontend/src/i18n/locales/zh.ts#L403-L470) 与 en 同步。

### P2 阶段（增强与清理）

**P2-1　差异自愈入口**
- 基于 `missing_in_db` / `missing_in_firewall` 提供一个“对账差异”视图：DB 有防火墙无 → 触发重封；防火墙有 DB 无 → 补建（复用现有对账逻辑），并支持跳转过滤。

**P2-2　偏差告警（配置化）**
- `blocked_diff` 超过阈值（新增系统设置项，复用事件告警配置机制，不硬编码）时告警。

**P2-3　状态机收敛评估（可选，低优先）**
- 评估 `block_state` 是否能并入 `compliance_status` 状态机，减少字段冗余；若风险大于收益则维持现状并文档化。

### P2-4　文档与版本同步
- 更新本说明文档、[release-notes.md](file:///home/dada/Codespace/TraeCN/TerminalAccessManager/docs/release-notes.md) 与版本跟踪表，执行完整业务链测试后按发布流程落地。

## 四、验证与回滚

- **验证（每阶段完成后）**：`./manage.sh update` 本地重建，核对三页数字——`Dashboard.blocked == 黑名单.已封锁(主) == 终端.非合规已封`；`终端.非合规待封 == 黑名单.待封锁(总)`；差异卡与对账差异清单一致。
- **回滚**：P0/P1 采用“新增接口 + 薄壳兼容”策略，任何页面可单独切回旧字段，避免一次性硬切换；对账缓存结构为递增字段，不影响旧读取方。

## 五、优先级建议

- **先做 P0-1 + P0-2**：没有清单与统一去重，其余都是空中楼阁，也是“对不上”的最直接来源。
- **再做 P1-1 → P1-4**：接口统一后，前端三页一次对齐，卡片数量从 6+7+3 降到 4+1+4+3 的量级。
- **最后 P2**：差异自愈/告警/状态机清理属优化，可独立排期。
