## 四、发布步骤

### 4.1 步骤一：版本号更新

```bash
# 更新 VERSION 文件
echo "3.6.8" > VERSION

# 更新 .env.example
sed -i 's/VERSION=3.6.7/VERSION=3.6.8/' .env.example

# 更新 docker-compose.yml
sed -i 's/VERSION: "${VERSION:-3.6.7}"/VERSION: "${VERSION:-3.6.8}"/' docker-compose.yml

# 更新 frontend/package.json
sed -i 's/"version": "3.6.7"/"version": "3.6.8"/' frontend/package.json
```

### 4.2 步骤二：构建验证

```bash
# 构建并重启服务
./manage.sh -y update

# 健康检查
./manage.sh health
```

### 4.3 步骤三：功能验证

| 验证项 | 验证方法 | 预期结果 |
|--------|----------|----------|
| 终端导出 | 在终端管理页面点击导出按钮 | 下载包含所有终端数据的CSV文件 |
| 终端筛选导出 | 设置筛选条件后点击导出 | 下载符合筛选条件的CSV文件 |
| 白名单导出 | 在白名单管理页面点击导出按钮 | 下载包含所有白名单数据的CSV文件 |
| 黑名单导出 | 在黑名单管理页面点击导出按钮 | 下载包含所有黑名单数据的CSV文件 |
| 创建通知渠道 | 在通知设置页面创建新渠道 | 返回201状态码，无500错误 |
| 白名单备注同步 | 添加白名单后查看终端管理 | 匹配的终端显示白名单备注 |
| 白名单删除同步 | 删除白名单后查看终端管理 | 相关终端备注被清除 |

### 4.4 步骤四：代码提交

```bash
# 添加所有变更文件
git add -A

# 创建发布提交
git commit -m "chore(release): v3.6.8 - 数据导出与通知渠道修复"

# 推送至远程仓库
git push origin develop
```

### 4.5 步骤五：创建Pull Request

- 从 `develop` 分支创建PR到 `main` 分支
- PR标题：`chore(release): v3.6.8`
- PR描述：包含变更摘要和验证结果
