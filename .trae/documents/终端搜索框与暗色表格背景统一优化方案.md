# 终端搜索框与暗色表格背景统一优化方案

> 文档版本：v1.0  更新日期：2026-08-28

## 一、问题概述

1. **终端管理页搜索框被挤压**：搜索框与众多筛选条件在同一行（`xl:flex-row`），在宽屏下搜索框 `flex-1` 被压缩到几乎不可见。
2. **暗色模式表格背景不统一**：
   - 黑名单（Blacklist）等数据表格：表头使用 `bg-background`，表体使用 `bg-card`，在暗色模式下两者颜色不一致（页面背景 4.9% vs 卡片 7%）。
   - 合规范围（ComplianceScope）页：仍使用硬编码浅色类名（`bg-white`/`bg-gray-50`/`text-gray-900` 等），在暗色模式下与全站语义化令牌风格不统一。

## 二、现状分析

- 全站数据表格的通用结构为：外层容器 `bg-card` + `<thead className="bg-background">` + `<tbody className="bg-card divide-y divide-border">`。
  - 由于 `thead` 用 `bg-background`，与 `bg-card` 的 `tbody` 在暗色模式下产生色差，这是黑名单页“表格背景与页面背景不一致”的根因。
- `ComplianceScope.tsx` 仍使用 Tailwind 浅色硬编码类，未迁移到语义令牌（semantic tokens），导致暗色模式下整页风格割裂。
- 语义令牌已在 `index.css` 中定义：`--background`、`--card`、`--muted`、`--foreground`、`--muted-foreground`、`--border` 等，其余页面均已使用 `bg-card`/`bg-background`/`text-foreground`/`text-muted-foreground`/`divide-border`/`border-border`。

## 三、修改方案

### 3.1 终端管理页搜索框独占一行（frontend/src/pages/Terminals.tsx）

目标：让搜索框独立占据一整行，筛选条件换行排列。

| 行号（当前） | 现状 | 修改为 |
|---|---|---|
| 525 | `<div className="flex flex-col xl:flex-row gap-4">` | `<div className="flex flex-col gap-4">` |
| 527 | `<div className="flex-1 relative">` | `<div className="relative">` |

说明：
- 移除 `xl:flex-row`，使外层容器始终为纵向排列（column）。
- 移除搜索框容器的 `flex-1`，使其在纵向布局下占满整行宽度（配合输入框 `w-full` 已存在）。
- 筛选条件容器 `flex flex-wrap items-center gap-2` 保持不变，将自然换行到下一行。

### 3.2 全站数据表格表头统一为 bg-card

目标：将数据表格表头 `bg-background` 统一改为 `bg-card`，使表头与表体背景一致，消除暗色模式色差。

统一规则：所有 `<thead className="bg-background">` → `<thead className="bg-card">`。

涉及文件与行号（共 11 处）：

|---|---|

| frontend/src/pages/Terminals.tsx | 762 |
| frontend/src/pages/Users.tsx | 315 |
| frontend/src/pages/Whitelist.tsx | 431 |
| frontend/src/pages/Roles.tsx | 133、359（两处） |
| frontend/src/pages/AuditLogs.tsx | 602 |
| frontend/src/components/datasources/DataSourcesTab.tsx | 424 |
| frontend/src/components/datasources/BindingsTab.tsx | 144 |
| frontend/src/components/datasources/ComplianceBaselinesTab.tsx | 465 |

说明：
- 已核查所有这些表的 `tbody` 均使用 `bg-card`，统一后表头/表体背景一致。
- 仅修改 `thead` 的 `bg-background`，不改动其它横向/纵向结构。

### 3.3 合规范围页全量语义令牌迁移（frontend/src/pages/ComplianceScope.tsx）

目标：将硬编码浅色类替换为语义令牌，与全站风格统一。

统一映射表：

| 现状（light-only） | 替换为（semantic） | 适用位置 |
|---|---|---|
| `bg-white`（表格容器/表体） | `bg-card` | 193、220 |
| `bg-gray-50`（表头） | `bg-card` | 195 |
| `bg-gray-50`（详情框/删除弹窗详情框） | `bg-muted` | 430 |
| `divide-gray-200` | `divide-border` | 194、220 |
| `border-gray-300` | `border-border` | 292、311、324、363、382、395 |
| `text-gray-900` | `text-foreground` | 176、228、461、480、485、490、494 |
| `text-gray-700` | `text-foreground` | 286、303、316、357、374、387、427 |
| `text-gray-500` | `text-muted-foreground` | 177、197–215、231、246、249、299、370、460、464、471、479、489、493 |
| `hover:bg-gray-50` | `hover:bg-muted/50` | 222 |

逐处改动清单：

1. **页面容器（173）**：`<div className="p-6">` → `<div className="min-h-full bg-background p-4 sm:p-6 lg:p-8">`（与 Blacklist/Roles 等页面容器一致）。
2. **页头标题（176/177）**：`text-gray-900` → `text-foreground`；`text-gray-500` → `text-muted-foreground`。
3. **表格容器（193）**：`bg-white shadow` → `bg-card border border-border shadow-sm`。
4. **表格（194/195/220）**：`divide-gray-200` → `divide-border`；`bg-gray-50` → `bg-card`；`divide-gray-200 bg-white` → `divide-border bg-card`。
5. **表头 th（197–215）**：7 处 `text-gray-500` → `text-muted-foreground`。
6. **表行 hover（222）**：`hover:bg-gray-50` → `hover:bg-muted/50`。
7. **类型徽标（224）**：`bg-blue-100 ... text-blue-800` → 增加暗色变体 `dark:bg-blue-500/15 dark:text-blue-400`（保留浅色语义）。
8. **单元格值（228）**：`text-gray-900` → `text-foreground`。
9. **描述/创建者/时间（231/246/249）**：`text-gray-500` → `text-muted-foreground`。
10. **启用/禁用切换徽标（237–241）**：
    - 启用态：`bg-green-100 text-green-800 hover:bg-green-200` → `bg-green-100 text-green-800 hover:bg-green-200 dark:bg-green-500/15 dark:text-green-400 dark:hover:bg-green-500/25`。
    - 禁用态：`bg-gray-100 text-gray-500 hover:bg-gray-200` → `bg-gray-100 text-gray-500 hover:bg-gray-200 dark:bg-muted dark:text-muted-foreground dark:hover:bg-muted/80`。
11. **表单 label（286/303/316/357/374/387）**：`text-gray-700` → `text-foreground`。
12. **表单输入框（292/311/324/363/382/395）**：`border-gray-300` → `border-border`（其余 focus 样式保留，输入/选择/文本域文字色由全局 `index.css` 的 `input, select, textarea { @apply text-foreground; }` 兜底）。
13. **表单辅助说明（299/370）**：`text-gray-500` → `text-muted-foreground`。
14. **表单错误提示框（329/400）**：`bg-red-50 p-3 text-sm text-red-600` → `bg-red-50 p-3 text-sm text-red-600 dark:bg-red-500/10 dark:text-red-400`。
15. **删除确认弹窗（427/430）**：正文 `text-gray-700` → `text-foreground`；详情框 `bg-gray-50` → `bg-muted`。
16. **详情弹窗（460–494）**：所有 `text-gray-500` → `text-muted-foreground`，所有 `text-gray-900` → `text-foreground`；启用/禁用徽标（467/471）同第 10 条增加暗色变体。

## 四、假设与决策

- 全站统一采用「表头与表体同为 `bg-card`」的规则，不做差异化处理。
- 合规范围页的徽标色保留原浅色语义，仅通过 `dark:` 变体增强暗色可读性，不改变亮色模式外观。
- 终端管理页仅调整布局类名，不改动筛选逻辑、状态变量或排序逻辑。

## 五、验证步骤

1. 前端热更新/重建后，进入「终端管理」页：
   - 搜索框应独占一行且宽度正常；筛选条件在下一行自动换行；收窄浏览器宽度无横向溢出/挤压。
2. 切换暗色模式，检查以下页面数据表格：黑名单、终端、用户、白名单、角色、审计日志、数据源（数据源/绑定/合规基线）。
   - 表头与表体背景应一致（均为 `bg-card`），与页面背景（`bg-background`）层次清晰。
3. 切换暗色/亮色模式检查「合规范围」页：
   - 表格容器/表头/表体背景、文字、边框、分割线在两种模式下均清晰可读且与全站风格一致。
   - 新增/编辑/删除/详情弹窗内 label、输入框、辅助文字、错误提示在暗色下可读。
4. 运行前端类型检查/构建（如项目配置的 `frontend` 构建脚本），确认无 JSX/类名错误。

## 六、影响范围

- 仅前端表现层（`className` 调整），无后端、接口、数据结构或业务逻辑改动。
- 不涉及 `manage.sh`、Docker 配置或数据库变更。
