# 开发环境增强 + .env 分离方案

> 文档版本：v1.0  更新日期：2026-06-18

---

## 一、现状问题

### 1.1 docker-compose.dev.yml 价值太低

当前 dev overlay 仅替换 nginx 配置文件（HTTP vs HTTPS），开发环境缺乏真正的开发便利：

| 开发者需求 | 当前状态 | 影响 |
|-----------|---------|------|
| 后端代码热重载 | ❌ 需 `dc build && dc up -d` | 每次代码改动需重建镜像，耗时 1-2 分钟 |
| 前端 HMR | ❌ 需 `dc build && dc up -d` | 同上 |
| 数据库直连调试 | ❌ postgres 端口未暴露 | 无法用 DBeaver/pgAdmin 连接 |
| Redis 直连调试 | ❌ redis 端口未暴露 | 无法用 RedisInsight 连接 |
| 后端远程调试 | ❌ 无 debugpy 端口 | 无法 IDE 断点调试 |
| 环境变量分离 | ❌ dev/prod 共用 .env | 切换环境需重新部署 |

### 1.2 .env 分离缺失

当前 dev/prod 使用同一 `.env` 文件，`manage.sh deploy --dev` 和 `deploy --prod` 都写入同一文件。切换环境时所有配置被覆盖。

---

## 二、方案设计

### 2.1 .env + .env.override 模式

```
.env.example     # 模板（所有变量 + 注释，纳入版本控制）
.env             # 共享基础配置（PROJECT_NAME, VERSION, DB_HOST, TZ 等）
.env.dev         # 开发环境覆盖（ENVIRONMENT=development, DEBUG=true, 弱密码, LOG_LEVEL=DEBUG）
.env.prod        # 生产环境覆盖（ENVIRONMENT=production, DEBUG=false, 强密码, LOG_LEVEL=WARNING）
```

**分层逻辑**：
- `.env` 存放所有环境共享的配置（项目名、版本、数据库主机、时区等）
- `.env.dev` / `.env.prod` 仅存放环境差异配置，覆盖 `.env` 中的同名变量
- docker-compose.yml 通过 `env_file` 指令加载两个文件

**docker-compose.yml 修改**：
```yaml
services:
  backend:
    env_file:
      - .env
      - .env.${ENVIRONMENT:-development}
```

**manage.sh 修改**：
- `deploy --dev` 生成 `.env` + `.env.dev`
- `deploy --prod` 生成 `.env` + `.env.prod`
- `dc()` 函数传递 `--env-file .env --env-file .env.${ENVIRONMENT:-development}`

### 2.2 docker-compose.dev.yml 增强

在现有 nginx 配置替换基础上，增加开发便利：

| 增强项 | 具体内容 | 理由 |
|--------|---------|------|
| 后端源码挂载 | `./backend:/app` + uvicorn `--reload` | 代码修改自动生效，无需重建 |
| 前端开发服务器 | 暴露 3000 端口，vite dev server + HMR | 前端热更新，无需重建 |
| Postgres 端口暴露 | `5432:5432` | DBeaver/pgAdmin 调试 |
| Redis 端口暴露 | `6379:6379` | RedisInsight 调试 |
| 后端调试端口 | `5678:5678` (debugpy) | IDE 远程断点调试 |
| 日志级别 | `LOG_LEVEL=DEBUG` | 详细日志便于排查 |
| 关闭资源限制 | 移除 `deploy.resources.limits` | 开发环境不需要限制 |

## 三、详细实施步骤

### 步骤 1: 创建 .env.dev 和 .env.prod 模板

**文件**: `.env.dev`（新建，纳入版本控制）

```env
# ==============================================================================
# Development Environment Override
# ==============================================================================
# This file overrides .env values for development environment.
# Only environment-specific values are listed here.

ENVIRONMENT=development
DEBUG=true
LOG_LEVEL=DEBUG

# Development passwords (auto-generated by manage.sh deploy --dev)
DB_PASSWORD=dev_db_pass_placeholder
REDIS_PASSWORD=dev_redis_pass_placeholder
SECRET_KEY=dev_secret_key_placeholder
ENCRYPTION_KEY=dev_encryption_key_placeholder
ADMIN_PASSWORD=Admin123

# Relaxed rate limits for development
RATE_LIMIT_PER_MINUTE=120
AUTH_RATE_LIMIT_PER_MINUTE=30

# CORS - allow localhost
BACKEND_CORS_ORIGINS=["http://localhost","http://localhost:80","http://localhost:3000","http://localhost:8080"]

# Enable manage.sh logging
TAM_LOG_ENABLED=true
```

**文件**: `.env.prod`（新建，纳入版本控制，仅含占位符）

```env
# ==============================================================================
# Production Environment Override
# ==============================================================================
# This file overrides .env values for production environment.
# IMPORTANT: All passwords and secrets MUST be changed before deployment!
# Use `./manage.sh deploy --prod` to configure interactively.

ENVIRONMENT=production
DEBUG=false
LOG_LEVEL=WARNING

# Production passwords (MUST be changed - use deploy --prod to configure)
DB_PASSWORD=CHANGE_ME_PRODUCTION_DB_PASSWORD
REDIS_PASSWORD=CHANGE_ME_PRODUCTION_REDIS_PASSWORD
SECRET_KEY=CHANGE_ME_PRODUCTION_SECRET_KEY
ENCRYPTION_KEY=CHANGE_ME_PRODUCTION_ENCRYPTION_KEY
ADMIN_PASSWORD=CHANGE_ME_PRODUCTION_ADMIN_PASSWORD

# Strict rate limits for production
RATE_LIMIT_PER_MINUTE=60
AUTH_RATE_LIMIT_PER_MINUTE=10

# CORS - restrict to production domain
BACKEND_CORS_ORIGINS=["https://your-domain.com"]

# Enable manage.sh logging
TAM_LOG_ENABLED=true
```

**文件**: `.env`（运行时生成，不纳入版本控制）

仅保留共享配置：
```env
# Shared configuration (generated by manage.sh deploy)
PROJECT_NAME=Terminal Access Manager
VERSION=3.3.1
API_V1_STR=/api/v1
ALGORITHM=HS256
TZ=Asia/Shanghai
COMPOSE_PROJECT_NAME=tam
DB_HOST=postgres
DB_PORT=5432
DB_USER=tam_admin
DB_NAME=tam_db
ACCESS_TOKEN_EXPIRE_MINUTES=30
REFRESH_TOKEN_EXPIRE_DAYS=7
MAX_LOGIN_ATTEMPTS=5
LOCKOUT_DURATION_MINUTES=15
CAPTCHA_THRESHOLD=3
ALLOW_REGISTRATION=false
UPLOAD_DIR=/app/uploads
```

### 步骤 2: 修改 docker-compose.yml — 添加 env_file

为 backend 和 frontend 服务添加 `env_file` 指令：

```yaml
services:
  backend:
    env_file:
      - .env
      - .env.${ENVIRONMENT:-development}
    # ... 其余不变

  frontend:
    env_file:
      - .env
      - .env.${ENVIRONMENT:-development}
    # ... 其余不变
```

注意：docker-compose.yml 中已有的 `environment:` 块保留，因为 `environment` 优先级高于 `env_file`，用于需要变量替换的场景（如 `DATABASE_URL` 的构建）。

### 步骤 3: 重写 docker-compose.dev.yml

**文件**: `docker-compose.dev.yml`

```yaml
# ==============================================================================
# Development Environment Override
# ==============================================================================
# Usage: docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d
# Or:    ENVIRONMENT=development ./manage.sh start
# ==============================================================================

services:
  backend:
    # Mount source code for hot-reload
    volumes:
      - ./backend:/app
      - tam-logs:/var/log/tam
      - upload_data:/app/uploads
    # Override command to enable uvicorn --reload
    command: uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload --reload-dir /app/app
    # Expose debug port for IDE remote debugging
    ports:
      - "127.0.0.1:8000:8000"
      - "127.0.0.1:5678:5678"
    # Override environment for development
    environment:
      - LOG_LEVEL=DEBUG
    # Remove resource limits for development
    deploy:
      resources: {}

  frontend:
    # In dev mode, run vite dev server with HMR instead of building
    build:
      context: ./frontend
      dockerfile: Dockerfile.dev
    ports:
      - "127.0.0.1:3000:3000"
    volumes:
      - ./frontend/src:/app/src
      - ./frontend/public:/app/public
      - ./frontend/index.html:/app/index.html
      - ./frontend/vite.config.ts:/app/vite.config.ts
      - ./frontend/tailwind.config.js:/app/tailwind.config.js
      - ./frontend/tsconfig.json:/app/tsconfig.json
      - ./frontend/tsconfig.node.json:/app/tsconfig.node.json
      - ./frontend/postcss.config.js:/app/postcss.config.js
      - ./frontend/package.json:/app/package.json
    # Remove resource limits for development
    deploy:
      resources: {}
    # Don't restart - keep running for HMR
    restart: unless-stopped

  postgres:
    # Expose port for DBeaver/pgAdmin
    ports:
      - "127.0.0.1:5432:5432"

  redis:
    # Expose port for RedisInsight
    ports:
      - "127.0.0.1:6379:6379"

  nginx:
    # Use dev nginx config (HTTP only, relaxed rate limits)
    volumes:
      - ./nginx/etc/conf.d/tam.dev.conf:/etc/nginx/conf.d/default.conf
      - ./nginx/certs:/etc/nginx/ssl:ro
      - frontend_dist:/usr/share/nginx/html:ro
```

### 步骤 4: 创建 frontend/Dockerfile.dev

**文件**: `frontend/Dockerfile.dev`（新建）

```dockerfile
# Development Dockerfile for Frontend - runs Vite dev server with HMR
FROM node:18-alpine

WORKDIR /app

# Install dependencies
COPY package.json package-lock.json* ./
RUN npm install

# Copy config files
COPY vite.config.ts tailwind.config.js postcss.config.js tsconfig.json tsconfig.node.json ./
COPY index.html ./

# Expose Vite dev server port
EXPOSE 3000

# Start Vite dev server with HMR
# --host 0.0.0.0 allows access from nginx and host
# --strictPort ensures port 3000 is used
CMD ["npm", "run", "dev", "--", "--host", "0.0.0.0", "--strictPort"]
```

### 步骤 5: 修改 manage.sh — 支持 .env 分离

**5.1 修改 `dc()` 函数** — 传递 env_file 参数：

```bash
dc() {
    local compose_files="-f ${SCRIPT_DIR}/docker-compose.yml"
    local env_mode
    env_mode=$(get_env "ENVIRONMENT" 2>/dev/null || echo "")
    if [ "${env_mode}" = "production" ] || [ "${env_mode}" = "prod" ]; then
        if [ -f "${SCRIPT_DIR}/docker-compose.prod.yml" ]; then
            compose_files="${compose_files} -f ${SCRIPT_DIR}/docker-compose.prod.yml"
        fi
    elif [ "${env_mode}" = "development" ] || [ "${env_mode}" = "dev" ]; then
        if [ -f "${SCRIPT_DIR}/docker-compose.dev.yml" ]; then
            compose_files="${compose_files} -f ${SCRIPT_DIR}/docker-compose.dev.yml"
        fi
    fi
    # Pass env files for variable resolution
    local env_files="--env-file ${ENV_FILE}"
    if [ -f "${SCRIPT_DIR}/.env.${env_mode}" ]; then
        env_files="${env_files} --env-file ${SCRIPT_DIR}/.env.${env_mode}"
    fi
    docker compose ${env_files} ${compose_files} "$@"
}
```

**5.2 修改 `_configure_dev_env()`** — 生成 `.env` + `.env.dev`：

- `.env` 仅包含共享配置（项目名、版本、DB_HOST、TZ 等）
- `.env.dev` 包含开发环境特有配置（密码、DEBUG=true、LOG_LEVEL=DEBUG 等）
- 自动生成密码写入 `.env.dev`

**5.3 修改 `_configure_production_wizard()`** — 生成 `.env` + `.env.prod`：

- `.env` 同上
- `.env.prod` 包含生产环境特有配置（强密码、DEBUG=false、LOG_LEVEL=WARNING 等）
- 交互式配置的密码写入 `.env.prod`

**5.4 修改 `check_weak_defaults()`** — 检查 `.env.prod` 而非 `.env`：

- 当前检查 `.env` 中的弱密码
- 修改后检查 `.env.prod` 中的弱密码

### 步骤 6: 更新 .gitignore

添加：
```
.env
```

确保 `.env.dev` 和 `.env.prod` 模板文件纳入版本控制，但运行时 `.env` 不纳入。

### 步骤 7: 更新 .env.example

精简 `.env.example`，仅保留共享配置 + 注释说明环境差异配置在 `.env.dev` / `.env.prod` 中。

## 五、验证步骤

1. **开发环境部署**: `./manage.sh deploy --dev` → 验证生成 `.env` + `.env.dev`
2. **后端热重载**: 修改 backend 代码 → 验证 uvicorn 自动重载
3. **前端 HMR**: 修改 frontend 代码 → 验证浏览器自动更新
4. **数据库直连**: DBeaver 连接 `localhost:5432` → 验证可连接
5. **Redis 直连**: RedisInsight 连接 `localhost:6379` → 验证可连接
6. **生产环境部署**: `./manage.sh deploy --prod` → 验证生成 `.env` + `.env.prod`
7. **弱密码检查**: `.env.prod` 中保留占位符 → 验证 `check_weak_defaults()` 阻止部署
8. **环境切换**: 从 dev 切换到 prod → 验证 `.env` 共享配置不变
9. **docker compose config**: 验证 env_file 变量正确合并
