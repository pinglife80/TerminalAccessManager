# Git Flow 回退与重新发布计划（修正版）

## 问题分析

**现状**：v3.6.9 版本发布时直接在 `main` 分支提交（commit `956aa3e`），跳过了 Git Flow 规范流程。

**当前分支状态**：
```
main:      956aa3e (v3.6.9 commit) → tag v3.6.9
develop:   1acfc5e (v3.6.8)
```

**分支保护规则**（来自 [git-workflow-guide.md](file:///home/dada/Codespace/TraeCN/TerminalAccessManager/docs/git-workflow-guide.md)）：
- **main**: Require PR before merging, CI must pass, branches must be up to date
- **develop**: No PR required, only force push protection

**约束**：main 分支有保护规则，不能直接 force push，必须使用 `git revert`

## 回退方案

### Step 1：回退 main 分支上的 v3.6.9 提交

```bash
# 1.1 切换到 main 分支
git checkout main
git pull origin main

# 1.2 确认要回退的 commit
git log --oneline -3

# 1.3 Revert v3.6.9 commit（创建新的撤销提交，不破坏分支保护）
git revert 956aa3e --no-edit

# 1.4 推送 revert 提交到远程
git push origin main
```

### Step 2：删除远程 v3.6.9 tag

```bash
# 2.1 删除本地 tag
git tag -d v3.6.9

# 2.2 删除远程 tag
git push origin :v3.6.9
```

### Step 3：验证回退结果

```bash
# 3.1 查看分支状态
git log --oneline -5 --all --graph

# 3.2 验证 main 回到 v3.6.8
git describe --tags --abbrev=0
# 预期输出：v3.6.8
```

## 重新发布流程（遵循 Git Flow Guide 发布日流程）

### Phase 1：在 develop 上提交变更

```bash
# 1. 切换到 develop 分支
git checkout develop
git pull origin develop

# 2. 应用 v3.6.9 的变更（直接在 develop 上提交，无需创建 bugfix 分支）
git cherry-pick 956aa3e --no-commit

# 3. 检查变更内容
git status

# 4. 重新提交（遵循 Conventional Commits）
git add -A
git commit -m "fix(compliance): unify compliance check paths with shared method"

# 5. 运行测试
./manage.sh test

# 6. 更新版本号和文档
./manage.sh version bump 3.6.9
git add -A
git commit -m "chore(release): prepare v3.6.9"

# 7. 推送到远程
git push origin develop
```

### Phase 2：创建 Release PR（develop → main）

**在 GitHub 上操作**：

1. 进入仓库 → Pull Requests → New pull request
2. base: `main` ← compare: `develop`
3. 填写 PR 标题：`release: v3.6.9 - compliance logic optimization`
4. 填写 PR 描述（从 changelog.md 复制）
5. 提交 PR

**CI 自动运行**：
- backend-lint
- backend-test
- frontend-lint
- frontend-test

### Phase 3：合并到 main

**CI 通过后**：

1. 在 GitHub PR 页面点击 **Merge pull request**
2. 使用默认合并方式（Create a merge commit）

### Phase 4：打 tag 和创建 Release

```bash
# 1. 切换到 main，拉取最新
git checkout main
git pull origin main

# 2. 创建带注释的 tag
git tag -a v3.6.9 -m "release v3.6.9: compliance logic optimization"

# 3. 推送 tag 到远程
git push origin v3.6.9
```

**在 GitHub 上创建 Release**：

1. 进入仓库 → Releases → Draft a new release
2. Choose a tag: `v3.6.9`
3. Release title: `v3.6.9`
4. 填写 Release notes（从 changelog.md 复制）
5. 点击 **Publish release**

### Phase 5：同步回 develop

```bash
# 1. 切换到 develop
git checkout develop

# 2. 合并 main（确保 develop 包含 tag）
git merge main

# 3. 推送到远程
git push origin develop
```

## 关键注意事项

1. **直接在 develop 上提交**：根据文档"单人开发简化模式"，小改动无需创建 feature/bugfix 分支
2. **禁止直接 push 到 main**：main 有分支保护，必须通过 PR 合并
3. **CI 必须全部通过**：否则无法合并到 main
4. **tag 只在 main 上创建**：确保生产版本的 tag 与 main 分支一致
5. **同步回 develop**：每次发布后确保 develop 包含最新的 main 代码
6. **Conventional Commits**：所有提交遵循规范格式
