## 1. 系统概述

### 1.1 平台简介

终端准入管控平台是一套企业级网络终端访问控制系统，通过自动化流程实现对网络中终端设备的合规性检查与访问控制。平台核心工作流程为：

```
数据采集 → 合规判定 → 封堵/解封
```

**核心能力：**

- **数据采集**：通过 ARP 数据源（SSH/API 协议）从网络交换机自动采集终端信息
- **合规判定**：将采集数据与 IPGuard 数据库基准进行比对，判定终端合规状态
- **自动封堵**：对不合规终端自动通过深信服防火墙执行封堵策略
- **白名单豁免**：支持对特定终端设置白名单，豁免合规检查
- **审计追溯**：全量操作审计日志，支持按类别检索与导出

### 1.2 合规状态说明

系统定义了四种终端合规状态：

| 状态 | 标识 | 说明 |
|------|------|------|
| 合规 | `compliant` | 终端信息在 IPGuard 基准中存在匹配记录 |
| 不合规 | `non_compliant` | 终端信息未在 IPGuard 基准中找到匹配记录 |
| 豁免 | `bypass` | 终端已加入白名单，跳过合规检查 |
| 未知 | `unknown` | 终端尚未进行合规判定（通常为刚采集、尚未同步基准的数据） |

> **注意：** 豁免（bypass）状态的终端不会被自动封堵，即使其不在合规基准中。

### 1.3 角色与权限

系统采用基于角色的访问控制（RBAC），共定义 5 种角色：

| 角色 | 标识 | 权限范围 |
|------|------|----------|
| 超级管理员 | `superadmin` | 拥有全部权限，可管理所有租户与系统级配置，不受租户隔离限制 |
| 管理员 | `admin` | 拥有当前租户内全部功能权限，可管理用户、配置、数据源等 |
| 操作员 | `operator` | 可执行终端封堵/解封、白名单管理、数据源同步等日常操作 |
| 审计员 | `auditor` | 可查看所有数据和审计日志，但不可执行变更操作 |
| 查看者 | `viewer` | 仅可查看仪表板和终端列表，无任何操作权限 |

**权限矩阵概览：**

| 功能模块 | superadmin | admin | operator | auditor | viewer |
|----------|:----------:|:-----:|:--------:|:-------:|:------:|
| 仪表板 | ✅ | ✅ | ✅ | ✅ | ✅ |
| 终端管理 | ✅ | ✅ | ✅ | 👁️ | 👁️ |
| 封堵/解封 | ✅ | ✅ | ✅ | ❌ | ❌ |
| 白名单管理 | ✅ | ✅ | ✅ | 👁️ | ❌ |
| 黑名单管理 | ✅ | ✅ | ✅ | 👁️ | ❌ |
| 数据源管理 | ✅ | ✅ | ✅ | 👁️ | ❌ |
| 合规基准 | ✅ | ✅ | ✅ | 👁️ | ❌ |
| 审计日志 | ✅ | ✅ | ❌ | ✅ | ❌ |
| 用户管理 | ✅ | ✅ | ❌ | ❌ | ❌ |
| 系统设置 | ✅ | ✅ | ❌ | ❌ | ❌ |

> ✅ 可操作  👁️ 仅查看  ❌ 无权限

## 2. 登录与认证

### 2.1 访问系统

1. 打开浏览器，访问系统地址：`https://<HOST_IP>:8443`
2. 系统将显示登录页面

> **注意：** 系统使用 HTTPS 协议（默认端口 8443），请确保浏览器允许访问该端口。如出现证书警告，请根据企业安全策略确认是否继续访问。

### 2.2 登录操作

1. 在登录页面输入用户名和密码
2. 输入验证码（如页面显示验证码）
3. 点击 **登录** 按钮

**默认管理员账号：**

| 字段 | 值 |
|------|-----|
| 用户名 | `admin` |
| 初始密码 | `Admin123` |

> ⚠️ **安全提示：** 首次登录后请立即修改默认密码。默认密码仅用于初始化，长期使用默认密码将带来严重安全风险。

### 2.3 修改密码

1. 登录后，点击右上角用户头像或用户名
2. 选择 **修改密码**
3. 输入当前密码和新密码（需输入两次以确认）
4. 点击 **确认** 完成修改

**密码策略要求：**

- 密码长度不少于 8 个字符
- 须包含大写字母、小写字母、数字和特殊字符中的至少三种
- 新密码不能与最近使用过的密码相同

### 2.4 验证码

登录页面可能显示图形验证码，用于防止暴力破解。验证码不区分大小写。如看不清验证码，可点击验证码图片刷新。

### 2.5 账户锁定

为防止暴力破解，系统启用账户锁定机制：

- 连续输入错误密码达到设定次数后，账户将被自动锁定
- 锁定时间由系统安全配置决定
- 锁定期间即使输入正确密码也无法登录
- 锁定时间结束后账户自动解锁，或由管理员手动解锁

### 2.6 语言与主题切换

**切换界面语言：**

1. 点击页面右上角的语言切换按钮
2. 选择目标语言：
   - **中文**（默认）
   - **English**
   - **日本語**

**切换界面主题：**

1. 点击页面右上角的主题切换按钮
2. 选择：
   - **浅色主题**
   - **深色主题**
   - **跟随系统**（根据操作系统设置自动切换）

> 语言和主题偏好会保存在当前浏览器中，下次登录时自动应用。

## 3. 仪表板

### 3.1 概览

仪表板是登录后的默认页面，提供系统关键指标的概览视图，帮助用户快速了解当前终端合规状况。

### 3.2 统计指标

仪表板通常展示以下核心指标：

| 指标 | 说明 |
|------|------|
| 终端总数 | 当前系统中已采集的所有终端数量 |
| 合规终端数 | 状态为"合规"的终端数量 |
| 不合规终端数 | 状态为"不合规"的终端数量 |
| 豁免终端数 | 状态为"豁免"（白名单）的终端数量 |
| 未知终端数 | 状态为"未知"的终端数量 |
| 已封堵终端数 | 当前在黑名单中（已封堵）的终端数量 |
| 数据源状态 | 各数据源的连接与同步状态 |

### 3.3 快捷操作

仪表板提供以下快捷操作入口：

- **搜索终端**：跳转到终端管理页面
- **封堵终端**：跳转到黑名单管理页面
- **管理白名单**：跳转到白名单管理页面
- **审计日志**：跳转到审计日志页面

> 快捷操作的具体可用性取决于当前用户的角色权限。

## 4. 终端管理

### 4.1 终端列表

终端管理页面展示所有已采集的终端信息，包括：

| 字段 | 说明 |
|------|------|
| IP 地址 | 终端的 IP 地址 |
| MAC 地址 | 终端的 MAC 地址 |
| 合规状态 | 合规 / 不合规 / 豁免 / 未知 |
| 封堵状态 | 是否已被封堵 |
| 来源数据源 | 采集该终端信息的数据源名称 |
| 绑定状态 | 该终端对应的数据源绑定关系状态 |
| 防火墙标签 | 终端被封堵时使用的防火墙标签，仅在封堵状态下显示 |
| 最后更新时间 | 终端信息最后更新的时间 |

### 4.2 搜索与筛选

**按关键词搜索：**

1. 在搜索框中输入 IP 地址或 MAC 地址关键词
2. 系统实时过滤匹配的终端记录

**按条件筛选：**

- **合规状态筛选**：选择"合规"、"不合规"、"豁免"、"未知"进行过滤
- **封堵状态筛选**：选择"已封堵"或"未封堵"进行过滤
- **数据源筛选**：选择特定数据源查看其采集的终端

### 4.3 查看终端详情

点击终端列表中某条记录的操作按钮，可查看该终端的详细信息，包括：

- IP 地址、MAC 地址
- 合规状态、封堵状态
- 来源数据源（source_tag）
- 白名单匹配类型、黑名单匹配类型
- 防火墙标签（firewall_tag）：仅当终端处于封堵状态时显示，其他状态显示 "-"
- 添加时间、备注

### 4.4 封堵终端

当终端被判定为不合规时，可通过以下步骤进行封堵：

1. 在终端列表中，找到需要封堵的终端
2. 点击该终端行的 **封堵** 按钮
3. 在弹出的封堵确认对话框中：
   - **选择目标防火墙**：系统支持多防火墙，需选择执行封堵策略的防火墙
   - 确认封堵信息（IP/MAC 等）
4. 点击 **确认** 执行封堵

> ⚠️ **重要提示：**
> - 封堵操作将使目标终端无法访问网络，请谨慎操作
> - 如果终端对应的数据源未绑定任何防火墙，系统将显示绑定状态警告，提示用户先完成数据源与防火墙的绑定
> - 封堵操作会被记录到审计日志中

**关于防火墙选择：**

当一个数据源绑定了多个防火墙时，用户需要选择在哪个防火墙上执行封堵。封堵策略只会下发到选中的防火墙。

**绑定状态警告：**

如果终端所属的数据源未绑定防火墙，终端列表中会显示警告标识，提示该终端无法执行封堵操作。用户需要先在数据源管理中完成数据源与防火墙的绑定。

### 4.5 解封终端

终端的解封操作在黑名单管理中执行，详见 [第 6 章 黑名单管理](#6-黑名单管理)。

## 5. 白名单管理

### 5.1 白名单概述

白名单用于豁免特定终端的合规检查。加入白名单的终端将获得"豁免（bypass）"合规状态，不会被自动封堵，即使其不在 IPGuard 合规基准中。

**适用场景：**

- 访客设备，无需合规检查
- 临时接入的测试设备
- 特殊用途设备，无法满足合规要求但需保留网络访问

### 5.2 添加白名单

#### 在白名单管理页面添加

1. 进入 **白名单管理** 页面
2. 点击 **添加白名单** 按钮
3. 在弹出的对话框中填写信息：
   - **类型**：选择添加方式
     - **MAC 地址**：输入单个 MAC 地址（格式：`AA:BB:CC:DD:EE:FF`），匹配类型为 `mac_only`
     - **IP 地址**：输入单个 IP 地址（格式：`192.168.1.100`），匹配类型为 `single_ip`
     - **CIDR**：输入 CIDR 格式的地址段（格式：`192.168.1.0/24`），匹配类型为 `cidr`
     - **IP 范围**：输入起始和结束 IP 地址（格式：`192.168.1.1 - 192.168.1.100`），匹配类型为 `ip_range`
   - **备注**（必填）：填写添加原因或备注信息
4. 点击 **确认** 完成添加

#### 在终端管理页面添加

1. 在终端管理页面，找到需要添加白名单的终端
2. 点击终端行的操作按钮，选择 **添加到白名单**
3. 在弹出的对话框中选择匹配类型：
   - **仅 MAC**：仅根据 MAC 地址匹配，匹配类型为 `mac_only`
   - **仅 IP**：仅根据 IP 地址匹配，匹配类型为 `single_ip`
   - **MAC + IP**：同时匹配 MAC 和 IP 地址，匹配类型为 `both`（双重匹配）
4. 填写 **备注**（必填）
5. 点击 **确认** 完成添加

> **注意：**
> - MAC 地址不区分大小写，系统会自动格式化
> - CIDR 和 IP 范围方式可一次性添加多个地址
> - 已在白名单中的地址不可重复添加
> - 备注为必填项，必须填写添加原因

### 5.3 查看白名单

白名单列表展示所有白名单条目，包含以下信息：

| 字段 | 说明 |
|------|------|
| 地址/范围 | 白名单的 MAC 地址、IP 地址或地址范围 |
| 类型 | MAC / IP / CIDR / 范围 |
| 添加时间 | 白名单创建时间 |
| 添加者 | 执行添加操作的用户 |
| 备注 | 备注信息 |

支持按类型和关键词进行筛选。

### 5.4 删除白名单

1. 在白名单列表中，选择需要删除的条目
2. 点击 **删除** 按钮
3. 在确认对话框中点击 **确认**

> ⚠️ **重要提示：** 删除白名单后，相关终端的合规状态将从"豁免"变为实际合规判定结果（合规或不合规）。如果终端变为不合规状态，可能被自动封堵策略处理。请在删除前确认影响范围。

### 5.5 白名单对合规状态的影响

| 操作 | 合规状态变化 |
|------|-------------|
| 添加白名单 | 终端状态 → 豁免（bypass） |
| 删除白名单 | 豁免（bypass） → 根据实际合规判定结果变为合规或非合规 |

## 6. 黑名单管理

### 6.1 黑名单概述

黑名单记录所有已被封堵的终端信息。终端被加入黑名单后，对应防火墙将阻止其网络访问。

### 6.2 黑名单列表

黑名单列表展示所有被封堵的终端信息：

| 字段 | 说明 |
|------|------|
| IP 地址 | 被封堵终端的 IP 地址 |
| MAC 地址 | 被封堵终端的 MAC 地址 |
| 封堵方式 | 手动封堵 / 自动封堵 |
| 封堵防火墙 | 执行封堵的防火墙名称 |
| 封堵时间 | 封堵操作执行时间 |
| 操作者 | 执行封堵的用户（自动封堵时显示"系统"） |

### 6.3 筛选与过滤

支持以下筛选条件：

- **封堵方式**：手动封堵 / 自动封堵
- **防火墙**：按执行封堵的防火墙筛选
- **时间范围**：按封堵时间筛选
- **关键词搜索**：按 IP 或 MAC 地址搜索

### 6.4 查看封堵详情

点击黑名单中的某条记录，可查看封堵详情：

- 终端 IP 地址、MAC 地址
- 封堵原因
- 封堵操作者（手动封堵显示用户名，自动封堵显示"系统"）
- 执行封堵的防火墙标签（firewall_tag）
- 封堵类型（手动/自动）
- 封堵时间、过期时间
- 当前状态（活跃/已过期）

### 6.5 解封终端

1. 在黑名单列表中，找到需要解封的终端
2. 点击 **解封** 按钮
3. 在确认对话框中确认解封操作
4. 系统将向对应防火墙下发解封策略

> **注意：** 解封操作仅移除防火墙封堵策略，不会改变终端的合规状态。如果终端仍为不合规状态，在下次自动合规检查中可能再次被自动封堵。如需永久豁免，请将其加入白名单。

### 6.6 手动封堵与自动封堵的区别

| 特征 | 手动封堵 | 自动封堵 |
|------|---------|---------|
| 触发方式 | 用户在终端管理页面手动操作 | 系统根据合规判定结果自动执行 |
| 操作者显示 | 具体用户名 | "系统" |
| 解封方式 | 手动解封 | 手动解封（不会自动解封） |
| 审计记录 | 记录操作用户 | 记录为系统自动操作 |

## 7. 数据源管理

### 7.1 数据源概述

数据源是平台获取终端信息和执行封堵策略的通道。系统支持两类数据源：

| 类型 | 说明 | 用途 |
|------|------|------|
| ARP 数据源 | 通过 SSH 或 API 协议从网络交换机采集 ARP 表数据 | 获取终端 IP/MAC 信息 |
| 深信服防火墙 | 连接深信服防火墙设备 | 执行封堵/解封策略 |

### 7.2 ARP 数据源管理

#### 7.2.1 添加 ARP 数据源

1. 进入 **数据源管理** 页面
2. 点击 **添加数据源**
3. 选择类型为 **ARP 数据源**
4. 填写配置信息：
   - **名称**：数据源的唯一标识名称
   - **协议**：选择 SSH 或 API
   - **主机地址**：交换机 IP 地址
   - **端口**：SSH 端口（默认 22）或 API 端口
   - **认证信息**：
     - SSH：用户名/密码 或 SSH 密钥
     - API：API 地址与认证 Token
5. 点击 **测试连接** 验证配置是否正确
6. 点击 **确认** 保存

#### 7.2.2 启用/禁用数据源

- **启用**：数据源将按计划自动采集数据
- **禁用**：数据源停止采集，已有数据保留但不再更新

操作方式：在数据源列表中，切换启用/禁用开关。

> **注意：** 禁用数据源后，该数据源采集的终端信息仍会保留在系统中，但不会更新。已绑定的防火墙绑定关系不受影响。

#### 7.2.3 同步数据

1. 在数据源列表中，点击目标数据源的 **同步** 按钮
2. 系统将立即从交换机拉取最新 ARP 数据
3. 同步完成后，终端列表将更新

> 同步操作是手动的即时同步。数据源启用后也会按计划自动同步。

### 7.3 深信服防火墙管理（Operation Source）

深信服防火墙类型的数据源在数据源管理页面的 **Operation Source** 标签页中独立管理，位于 Data Sources 和 Bindings 标签页之间。

#### 7.3.1 添加深信服防火墙

1. 进入 **数据源管理** 页面
2. 切换到 **Operation Source** 标签页
3. 点击 **添加操作源**
4. 填写配置信息：
   - **名称**：防火墙的唯一标识名称
   - **主机地址**：防火墙管理 IP 地址
   - **端口**：管理端口
   - **认证信息**：用户名/密码 或 API Key
5. 点击 **测试连接** 验证配置是否正确
6. 点击 **确认** 保存

> **说明：** 深信服防火墙是 push-type 数据源，仅用于执行封堵/解封策略，不需要同步 ARP 数据。测试连接成功后，"Last Test" 列会更新最后测试时间。

### 7.4 数据源绑定

数据源绑定用于建立 ARP 数据源与深信服防火墙之间的关联关系。绑定后，从该 ARP 数据源采集的终端可通过绑定的防火墙执行封堵/解封。

#### 7.4.1 创建绑定

1. 在数据源管理页面，切换到 **绑定** 标签页
2. 点击 **添加绑定**
3. 选择 ARP 数据源和深信服防火墙
4. 点击 **确认** 创建绑定

> **说明：** 一个 ARP 数据源可以绑定多个防火墙，一个防火墙也可以被多个 ARP 数据源绑定。

#### 7.4.2 绑定状态警告

如果终端所属的 ARP 数据源未绑定任何防火墙，在终端管理页面中该终端会显示绑定状态警告，提示用户：

- 该终端无法执行封堵操作
- 需要先在数据源管理中完成绑定

### 7.5 删除数据源

系统对数据源删除采用两阶段确认机制，防止误删：

1. 在数据源列表中，点击目标数据源的 **删除** 按钮
2. **第一阶段 — 预览**：系统显示删除影响预览，包括：
   - 该数据源采集的终端数量
   - 关联的绑定关系数量
   - 其他受影响的资源
3. **第二阶段 — 确认**：确认删除影响后，输入数据源名称或点击确认按钮完成删除

> ⚠️ **警告：** 删除数据源是不可逆操作。删除后，该数据源采集的终端信息可能受到影响，关联的绑定关系也将被移除。

## 8. 合规基准

### 8.1 合规基准概述

合规基准是终端合规判定的依据，来源于 IPGuard 数据库。系统将采集到的终端信息与合规基准进行比对，判定终端是否合规。

### 8.2 IPGuard 集成

系统通过 IPGuard 数据库集成获取合规基准数据。IPGuard 数据库中记录了企业网络中合规终端的信息，包括：

- 已注册终端的 IP/MAC 地址
- 终端资产归属信息
- 终端安全配置基线

### 8.3 同步合规基准

1. 进入 **合规基准** 页面
2. 点击 **同步** 按钮
3. 系统将从 IPGuard 数据库拉取最新基准数据
4. 同步完成后，所有终端的合规状态将根据新基准重新判定

> **注意：** 同步合规基准可能需要一定时间，取决于 IPGuard 数据库的数据量。同步期间系统仍可正常使用，但合规状态可能在同步完成后发生变化。

### 8.4 查看基准信息

合规基准以数据源管理页面内的标签页形式展示，包含：

- 基准列表（名称、类型、标签、启用状态、最后同步时间）
- 每条基准的操作按钮：测试连接、编辑、同步、删除

### 8.5 删除合规基准

系统对合规基准删除同样采用两阶段确认机制：

1. 点击 **删除** 按钮
2. **第一阶段 — 预览**：系统显示删除影响预览，包括：
   - 当前基准中的记录数量
   - 删除后受影响的终端数量
   - 合规状态将变为"未知"的终端数量
3. **第二阶段 — 确认**：确认删除影响后，完成删除

> ⚠️ **警告：** 删除合规基准后，所有终端的合规状态将变为"未知"，直到重新同步基准数据。这可能导致自动封堵策略无法正常工作。

## 9. 审计日志

### 9.1 审计日志概述

审计日志记录系统中所有关键操作，用于安全审计和问题追溯。所有操作均以 `verb_resource` 格式命名，例如：

- `create_user`：创建用户
- `delete_whitelist`：删除白名单
- `block_terminal`：封堵终端
- `login_auth`：登录认证

### 9.2 操作类别

审计日志按操作类别分为 9 大类：

| 类别 | 标识 | 包含的操作示例 |
|------|------|---------------|
| 认证 | `auth` | 登录、登出、修改密码、账户锁定 |
| 终端 | `terminal` | 查看终端、封堵终端、解封终端 |
| 白名单 | `whitelist` | 添加白名单、删除白名单 |
| 黑名单 | `blacklist` | 查看黑名单、解封操作 |
| 数据源 | `datasource` | 创建/编辑/删除数据源、同步数据、绑定管理 |
| 用户 | `user` | 创建/编辑/停用用户、角色分配 |
| 配置 | `config` | 系统设置变更、品牌定制修改 |
| 合规 | `compliance` | 同步基准、合规判定 |
| 系统 | `system` | 系统启动、定时任务执行、异常告警 |

### 9.3 搜索与筛选

审计日志页面提供丰富的筛选条件：

1. **操作类别**：从 9 大类中选择
2. **时间范围**：选择起止日期时间
3. **操作者**：按执行操作的用户筛选
4. **操作动作**：按具体的 `verb_resource` 动作筛选
5. **关键词搜索**：在日志详情中搜索关键词

### 9.4 查看日志详情

点击审计日志列表中的某条记录，可查看详细信息：

| 字段 | 说明 |
|------|------|
| 操作时间 | 操作执行的精确时间 |
| 操作者 | 执行操作的用户名 |
| 操作动作 | `verb_resource` 格式的动作标识 |
| 操作类别 | 所属操作类别 |
| 操作描述 | 操作的人类可读描述 |
| 操作详情 | 变更前后的数据对比（如适用） |
| 客户端 IP | 操作来源的客户端 IP 地址 |
| User-Agent | 操作来源的浏览器/客户端信息 |

### 9.5 导出审计日志

1. 设置筛选条件，定位需要导出的日志范围
2. 点击 **导出 CSV** 按钮
3. 系统将按当前筛选条件导出日志为 CSV 文件
4. 浏览器自动下载 CSV 文件

> **注意：** 导出的 CSV 文件使用 UTF-8 编码。在 Excel 中打开时，如出现中文乱码，请使用"数据 → 从文本/CSV"导入，并选择 UTF-8 编码。

## 10. 用户管理

### 10.1 用户管理概述

用户管理模块用于管理系统用户账号、角色分配和账号状态。仅 `superadmin` 和 `admin` 角色可访问此模块。

### 10.2 创建用户

1. 进入 **用户管理** 页面
2. 点击 **添加用户**
3. 填写用户信息：
   - **用户名**：唯一标识，创建后不可修改
   - **显示名称**：用户在界面上的显示名称
   - **密码**：初始密码，需符合密码策略
   - **角色**：从 5 种角色中选择
   - **邮箱**（可选）：用户邮箱地址
4. 点击 **确认** 创建用户

> **注意：** 新创建的用户首次登录时，建议修改初始密码。

### 10.3 编辑用户

1. 在用户列表中，点击目标用户的 **编辑** 按钮
2. 修改可编辑的字段（显示名称、角色、邮箱等）
3. 点击 **确认** 保存修改

> 用户名创建后不可修改。

### 10.4 停用/启用用户

1. 在用户列表中，切换用户的启用/停用状态
2. 停用后，该用户无法登录系统
3. 启用后，该用户可正常登录

> **注意：** 停用用户不会删除用户数据，仅阻止其登录。

### 10.5 角色分配

用户角色在创建时指定，也可在编辑时修改。修改角色后，用户的权限立即生效。

**角色分配注意事项：**

- 每个用户只能分配一个角色
- 角色变更后，用户当前的登录会话权限可能需要重新登录后生效
- 将用户角色降级后，该用户可能无法访问之前能访问的页面

### 10.6 超级管理员隔离

超级管理员（`superadmin`）具有以下特殊隔离机制：

- 超级管理员账号只能由其他超级管理员管理
- 普通管理员（`admin`）无法查看、编辑或停用超级管理员账号
- 超级管理员不受租户隔离限制，可管理所有租户的数据

### 10.7 初始管理员保护

系统初始化时创建的默认管理员账号（`admin`）具有特殊保护：

- 该账号不可被删除
- 该账号不可被停用
- 该账号的角色不可被降级

> 此保护机制确保系统始终至少有一个可用的管理员账号。

### 11.2 安全配置

#### 11.2.1 可配置项

| 配置项 | 配置键 | 默认值 | 说明 |
|--------|--------|--------|------|
| 最大登录尝试次数 | `max_login_attempts` | 5 | 连续输入错误密码达到此次数后锁定账户 |
| 锁定时长（分钟） | `lockout_duration_minutes` | 15 | 账户锁定后的自动解锁时间 |
| 验证码阈值 | `captcha_threshold` | 3 | 登录失败达到此次数后显示验证码 |
| 访问令牌过期时间（分钟） | `access_token_expire_minutes` | 30 | JWT 访问令牌的有效期 |
| 刷新令牌过期时间（天） | `refresh_token_expire_days` | 7 | JWT 刷新令牌的有效期 |
| 允许注册 | `allow_registration` | false | 是否允许用户自助注册 |

#### 11.2.2 密码策略（硬编码）

当前密码策略为固定规则，不可通过系统设置动态配置：

- 密码长度：8 ~ 128 个字符
- 必须包含大写字母、小写字母和数字中的至少三种
- 无特殊字符强制要求
- 无密码过期策略
- 无密码历史记录（允许重复使用旧密码）

> 修改密码策略需要修改后端代码（`backend/app/schemas/auth.py`）并重新部署。

#### 11.2.3 配置方式

通过 API 更新安全配置（需 `settings:write` 权限）：

```bash
# 更新锁定时长为 30 分钟
curl -X PUT https://<HOST_IP>:8443/api/v1/settings/lockout_duration_minutes \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"value": 30}'
```

> ⚠️ **注意：** 安全配置的修改会影响所有用户，请谨慎操作。建议在修改前通知所有用户。

### 11.3 认证提供者

认证提供者功能允许系统支持多种身份认证方式，包括本地认证和 LDAP 认证。

#### 11.3.1 认证流程

系统按优先级顺序尝试认证提供者：
1. 用户提交用户名密码
2. 系统按优先级顺序尝试各认证提供者
3. 任一提供者认证成功即登录成功
4. 所有提供者认证失败则返回"无效凭据"

#### 11.3.2 认证提供者类型

| 类型 | 说明 |
|------|------|
| 本地认证 | 使用系统内置用户数据库认证 |
| LDAP | 通过 LDAP/Active Directory 认证 |

#### 11.3.3 LDAP 配置

配置 LDAP 认证需要以下信息：

| 配置项 | 说明 |
|--------|------|
| 服务器地址 | LDAP 服务器地址和端口（如 `ldap://ldap.example.com:389`） |
| 基础 DN | LDAP 搜索基础（如 `dc=example,dc=com`） |
| 用户搜索基础 | 用户搜索范围（如 `ou=users`） |
| 用户搜索过滤器 | 用户搜索过滤条件（如 `(sAMAccountName={username})`） |
| 绑定 DN | 用于查询用户的服务账号 |
| 绑定密码 | 绑定账号的密码 |

> **注意：** 配置完成后请点击"测试连接"验证配置正确性。

#### 11.3.4 优先级说明

优先级数值越小，认证优先级越高。建议将本地认证设为最低优先级，确保 LDAP 不可用时仍可通过本地账号登录。

### 11.4 备份配置

备份配置功能用于管理系统数据的自动备份策略，支持定时备份、多种存储类型和加密选项。

#### 11.4.1 备份内容

| 类型 | 说明 | 默认 |
|------|------|------|
| 数据库备份 | 使用 pg_dump 备份 PostgreSQL 数据库 | 启用 |
| 配置文件备份 | 备份 docker-compose.yml 和 manage.sh | 启用 |
| 日志文件备份 | 备份系统日志文件 | 禁用 |

> **注意：** .env 文件包含敏感信息，不会被备份。

#### 11.4.2 存储类型

| 类型 | 说明 | 配置参数 |
|------|------|----------|
| 本地存储 | 备份文件存储在服务器本地 `backups/` 目录 | 无需额外配置 |
| SFTP | 备份文件上传至远程 SFTP 服务器 | 主机、端口、用户名、密码、远程路径 |
| FTP | 备份文件上传至远程 FTP 服务器 | 主机、端口、用户名、密码、远程路径、SSL 开关 |

**FTP SSL 说明：**
- 勾选"使用 SSL"时启用 FTPS（FTP over SSL/TLS）加密传输
- 未勾选时使用普通 FTP 明文传输，建议仅在内网环境使用

#### 11.4.3 备份策略

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| 启用备份 | 是否启用自动备份 | 禁用 |
| 备份频率 | 支持预设选择或自定义 CRON 表达式 | 每天凌晨2点 |
| 保留天数 | 备份文件保留天数，过期自动清理 | 7天 |
| 加密备份 | 是否对备份文件进行加密 | 启用 |

#### 11.4.4 备份频率设置

系统提供预设频率选择和自定义 CRON 表达式两种方式：

**预设频率：**

| 选项 | CRON 表达式 | 说明 |
|------|-------------|------|
| 每天凌晨2点 | `0 2 * * *` | 每天凌晨 2:00 执行备份 |
| 每天凌晨3点 | `0 3 * * *` | 每天凌晨 3:00 执行备份 |
| 每周日凌晨2点 | `0 2 * * 0` | 每周日凌晨 2:00 执行备份 |
| 自定义 | — | 使用自定义 CRON 表达式 |

**自定义 CRON 格式：**

当选择"自定义"时，需输入符合标准 CRON 5 字段格式的表达式：

```
分钟 小时 日 月 周
```

| 字段 | 范围 | 说明 |
|------|------|------|
| 分钟 | 0-59 | 执行的分钟数 |
| 小时 | 0-23 | 执行的小时数（24小时制） |
| 日 | 1-31 | 执行的日期 |
| 月 | 1-12 | 执行的月份 |
| 周 | 0-7 | 执行的星期（0 和 7 都表示周日） |

**常用 CRON 示例：**

| 表达式 | 说明 |
|--------|------|
| `0 2 * * *` | 每天凌晨 2:00 |
| `0 3 * * 0` | 每周日凌晨 3:00 |
| `30 1 * * 1-5` | 工作日（周一至周五）凌晨 1:30 |
| `0 0 1 * *` | 每月1日凌晨 0:00 |

> **提示：** 输入自定义 CRON 表达式后，系统会自动校验格式是否正确。

#### 11.4.5 测试配置

点击"测试配置"按钮可验证数据库连接和存储配置是否正常：

- **数据库测试**：验证 PostgreSQL 数据库连接是否正常
- **存储测试**：验证 SFTP/FTP 服务器连接和认证是否正常

测试结果会显示每个项目的状态（已连接/失败）。

#### 11.4.6 手动备份

#### 11.4.7 恢复备份

在备份列表中选择要恢复的备份文件，点击"恢复"按钮。恢复操作会覆盖当前数据库，请谨慎操作。

> ⚠️ **警告：** 恢复备份会清除当前所有数据，请确保已做好数据备份。

### 11.5 通知管理

#### 11.5.1 通知渠道类型

#### 11.5.2 事件类型

#### 11.5.3 邮件配置

| SMTP 端口 | SMTP 服务器端口（通常为 587） |

#### 11.5.4 测试通知

配置完成后点击"测试连接"按钮，系统会发送一条测试消息验证配置正确性。

#### 11.5.5 通知日志

通知日志记录所有已发送的通知及其状态，可按渠道名称、事件类型、状态筛选查看。

**日志管理操作**：

| 归档全部 | 批量归档30天前的所有日志 | notification:write |

**使用说明**：
- 点击日志操作列的"归档"按钮可将单条日志归档
- 点击页面右上角"归档全部"按钮批量归档30天前的日志
- 点击页面右上角"清理"按钮永久删除90天前的已归档日志
- 已归档的日志可通过筛选"已归档"状态查看

#### 11.5.6 消息模板

消息模板功能允许为每个事件-渠道组合自定义消息内容，使用 Jinja2 模板语法。支持通配符匹配和优先级控制。

**访问路径**：通知管理 → 模板

**常用变量**：

| 变量 | 说明 | 示例 |
|------|------|------|
| `event_type` | 事件类型 | `login` |
| `event_name` | 事件名称 | `用户登录` |
| `description` | 事件描述 | `用户成功登录系统` |
| `severity` | 事件等级 | `info` / `warning` / `critical` |
| `timestamp` | 事件时间 | `2026-07-03 12:00:00` |
| `data` | 事件数据对象 | `{{ data.username }}` |
| `source` | 事件来源 | `system` |

**通配符匹配**：

- 事件类型选择 `*`（通配符）可创建通用模板，匹配所有事件类型
- 匹配优先级：精确匹配优先于通配符匹配
- 示例：当事件类型为 `login` 时，优先使用 `login` 专用模板，若无则使用通配符 `*` 模板

**优先级控制**：

- 优先级字段用于控制多个模板的匹配顺序
- 数值越小优先级越高（默认值：100）
- 当存在多个匹配模板时，系统选择优先级最高的模板

**操作说明**：
1. 点击"新建模板"按钮创建模板
2. 选择事件类型（可选择 `*` 通配符匹配所有事件）和渠道类型
3. 设置优先级（可选，数值越小优先级越高）
4. 填写标题模板（可选）和正文模板
5. 点击"预览"查看渲染效果
6. 点击"保存"完成创建

> **提示**：模板支持 Markdown 格式（钉钉、企业微信、飞书渠道）和 HTML 格式（邮件渠道），请根据渠道类型选择合适的格式。

#### 11.5.7 通知规则

通知规则支持消息抑制、消息聚合和消息升级三种策略，用于减少通知骚扰并确保重要告警不被遗漏。支持通配符匹配和优先级控制。

**访问路径**：通知管理 → 规则

**规则类型**：

| 类型 | 说明 | 配置项 |
|------|------|--------|
| 消息抑制 | 同一事件在抑制窗口内仅发送一次，后续事件被静默 | suppress_window（秒） |
| 消息聚合 | 统计窗口内事件发生次数 | aggregate_window（秒） |
| 消息升级 | 达到阈值后自动提升事件严重等级 | escalate_threshold、escalate_severity |

**通配符匹配**：

- 事件类型选择 `*`（通配符）可创建通用规则，匹配所有事件类型
- 匹配优先级：精确匹配优先于通配符匹配
- 示例：当事件类型为 `login` 时，优先应用 `login` 专用规则，若无则应用通配符 `*` 规则

**优先级控制**：

- 优先级字段用于控制多个规则的执行顺序
- 数值越小优先级越高（默认值：100）
- 当存在多个匹配规则时，系统按优先级顺序执行所有匹配规则

**操作说明**：
1. 点击"新建规则"按钮创建规则
2. 选择事件类型（可选择 `*` 通配符匹配所有事件）和渠道名称（可选，留空表示所有渠道）
3. 设置优先级（可选，数值越小优先级越高）
4. 配置抑制窗口/升级阈值等参数
5. 点击"保存"完成创建

> **重要**：升级后的通知会自动绕过抑制规则，确保升级后的严重告警总能送达。

#### 11.5.8 监控统计

监控统计面板展示通知系统的运行状态，支持自动刷新。

**访问路径**：通知管理 → 监控统计

**统计指标**：

| 指标 | 说明 |
|------|------|
| 总发送量 | 累计处理的通知总数 |
| 成功数 | 发送成功的通知数 |
| 失败数 | 发送失败的通知数 |
| 成功率 | 成功数 / 总发送量 × 100% |
| 待处理 | 队列中等待发送的通知数 |
| 重试中 | 正在重试的通知数 |
| 已抑制 | 被抑制规则过滤的通知数 |
| 队列大小 | 当前主队列中的消息数 |
| 平均延迟 | 成功通知的平均发送耗时（毫秒） |
| 重试队列大小 | 待重试队列中的消息数 |

**功能说明**：
- 页面默认每 30 秒自动刷新统计数据
- 可点击右上角"刷新"按钮手动刷新
- 当存在失败通知时，显示"全部重试"按钮，可一键重发所有失败通知
- 各渠道成功率以进度条形式展示，便于快速识别问题渠道

#### 11.5.9 异步发送与重试机制

通知发送采用异步队列架构，不阻塞业务请求。失败的通知会自动重试。

**重试策略**：
- 最大重试次数：3 次
- 重试间隔：指数退避（首次 10 秒，后续翻倍）
- 首次重试：10 秒后
- 第二次重试：20 秒后
- 第三次重试：40 秒后
- 三次均失败：标记为最终失败

**手动重试**：
- 在通知日志中可对单条失败通知点击"重试"
- 在监控统计页面可点击"全部重试"批量重发所有失败通知

### 11.7 合规配置

合规配置用于调整合规判定引擎的行为参数，平衡判定灵敏度与系统稳定性。

**访问路径**：系统设置 → 合规配置

#### 11.7.1 可配置项

| 配置项 | 配置键 | 类型 | 默认值 | 取值范围 | 说明 |
|--------|--------|------|--------|---------|------|
| 合规状态翻转确认阈值 | `compliance_confirm_threshold` | int | 2 | 1-10 | compliant/bypass → non_compliant 状态翻转需连续 N 次同步确认 |

#### 11.7.2 翻转确认机制说明

由于 IPGuard 基线数据中的 `AGENT.AGT_IP_MAC_STR` 字段会因终端 DHCP 续租、agent 重连等场景产生瞬时波动，直接采用单次同步结果判定合规状态会导致"合规振荡"（终端在 compliant 与 non_compliant 之间频繁翻转，引发防火墙反复封堵/解封）。

为消除此现象，v3.7.0 引入翻转确认机制：

- **首次发现的新终端**（unknown → non_compliant）：立即生效并触发封堵，不受阈值影响
- **已合规终端转为不合规**（compliant/bypass → non_compliant）：需连续 N 次同步均判定为 non_compliant 后才正式变更状态并触发封堵
- N 由 `compliance_confirm_threshold` 配置项控制，默认为 2

> **配置建议**：
> - 网络环境稳定、IPGuard 数据波动小：可设为 1（即时判定）
> - 网络环境存在 DHCP 续租频繁、终端移动等波动：建议保持默认值 2
> - IPGuard 数据同步极不稳定：可适当调高至 3-5，但过高会延迟真实不合规终端的封堵

#### 11.7.3 配置方式

通过 API 更新合规配置（需 `settings:write` 权限）：

```bash
# 查看当前配置
curl https://<HOST_IP>:8443/api/v1/settings/compliance_confirm_threshold \
  -H "Authorization: Bearer <token>"

# 更新确认阈值为 3
curl -X PUT https://<HOST_IP>:8443/api/v1/settings/compliance_confirm_threshold \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"value": 3}'
```

> ⚠️ **注意：** 调整确认阈值会影响合规判定的响应速度。阈值越高，真实不合规终端被封堵的延迟越大；阈值越低，越容易受 IPGuard 数据波动影响产生合规振荡。修改后请观察至少一个完整同步周期（默认 10 分钟）的合规状态变化情况。

## 12. 常见问题（FAQ）

### Q1：终端显示"未知"状态是什么原因？

**A：** 终端显示"未知"状态通常有以下原因：
- 终端数据刚采集，尚未与合规基准进行比对
- 合规基准尚未同步（IPGuard 数据库未配置或同步失败）
- 合规基准已被删除，需要重新同步

### Q2：为什么无法封堵某个终端？

**A：** 可能的原因包括：
1. 该终端所属的 ARP 数据源未绑定任何防火墙 — 需先在数据源管理中创建绑定
2. 当前用户角色无封堵权限 — 需要 `operator` 及以上角色
3. 该终端已在白名单中（豁免状态）— 豁免终端不会被封堵
4. 防火墙连接异常 — 检查防火墙数据源的连接状态

### Q3：解封终端后，终端又被自动封堵了怎么办？

**A：** 这是因为终端仍为不合规状态。自动封堵策略会在合规检查时再次封堵不合规终端。解决方案：
1. 将终端加入白名单，使其获得豁免状态
2. 在 IPGuard 中注册该终端，使其变为合规状态

### Q4：深信服防火墙数据源为什么没有同步按钮？

**A：** 深信服防火墙数据源仅用于执行封堵/解封策略，不需要同步 ARP 数据，因此没有同步按钮。ARP 数据采集由 ARP 数据源负责。

### Q5：删除数据源时为什么要两步确认？

**A：** 两阶段删除（预览 + 确认）是为了防止误删。预览阶段会展示删除的影响范围（关联终端数、绑定关系等），帮助用户充分了解删除后果后再做决定。

### Q6：如何修改界面语言？

**A：** 点击页面右上角的语言切换按钮，可选择中文、English 或日本語。语言偏好保存在浏览器中，下次登录自动应用。

### Q7：忘记密码怎么办？

**A：** 系统暂不支持自助找回密码。请联系系统管理员（`admin` 或 `superadmin` 角色）重置密码。

### Q8：审计日志可以保存多长时间？

**A：** 审计日志的保留期限由系统配置决定。如需长期保存，建议定期使用 CSV 导出功能备份日志数据。

### Q9：超级管理员和普通管理员有什么区别？

**A：** 主要区别：
- 超级管理员不受租户隔离限制，可管理所有租户
- 超级管理员只能由其他超级管理员管理
- 超级管理员可管理其他超级管理员的账号
- 普通管理员无法查看或操作超级管理员账号

### Q10：白名单支持哪些地址格式？

**A：** 白名单支持以下四种格式：
- **MAC 地址**：如 `AA:BB:CC:DD:EE:FF`
- **IP 地址**：如 `192.168.1.100`
- **CIDR**：如 `192.168.1.0/24`
- **IP 范围**：如 `192.168.1.1 - 192.168.1.100`

### Q11：品牌定制修改后多久生效？

**A：** 品牌定制的修改保存后立即生效。如浏览器显示旧内容，请刷新页面或清除浏览器缓存。

### Q12：系统支持多少个防火墙？

**A：** 系统支持多防火墙部署，没有硬性数量限制。每个 ARP 数据源可绑定多个防火墙，封堵时需选择目标防火墙。
